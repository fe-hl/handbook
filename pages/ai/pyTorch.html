环境安装与学习地图 ​

核心概念

PyTorch 提供张量运算、自动求导和网络组件。训练是利用数据反复调整参数，不是把正确答案直接写进条件判断；推理则是固定参数后计算预测。框架能自动计算梯度，但不会自动修正错误标签、数据泄漏或不合理的评估方式。

从一个预测问题理解训练 ​

假设用面积预测房价，最简单的模型是 预测价格 = w × 面积 + b。面积是输入，真实价格是标签，w 和 b 是需要学习的参数。损失函数衡量预测与标签的差异；梯度说明参数变化会怎样影响损失；优化器据此更新参数。

               ^                                  |
               |                                  v
            更新参数 <- 优化器执行更新 <- 反向传播计算梯度

验证数据 -> 模型前向计算 -> 汇总指标 -> 选择模型与超参数
测试数据 -> 最终选定模型 -> 一次独立评估

张量：形状、类型、设备与内存 ​

核心概念

张量是带有形状、数据类型、设备及存储信息的多维数组。理解形状比记住层名更重要：绝大多数新手错误都可以先转换成“每个轴分别代表什么”。

标量、向量、矩阵与批次 ​

场景常见形状轴的含义
标量损失[]单个数值，无轴
一条特征[D]D 个特征
表格批次[N, D]样本数、特征数
图像批次[N, C, H, W]样本、通道、高、宽
token 批次[N, L]样本、序列位置
序列特征[N, L, E]样本、序列位置、嵌入维度
python
import torch

scalar = torch.tensor(3.0)
vector = torch.tensor([1.0, 2.0, 3.0])
matrix = torch.arange(12, dtype=torch.float32).reshape(3, 4)
print(scalar.shape, vector.shape, matrix.shape)
print(matrix.dtype, matrix.device, matrix.numel())
print(torch.zeros_like(matrix).shape)
print(matrix[:, 1])          # 第二列，形状 [3]
print(matrix[:, 1:2].shape)  # 保留列轴，形状 [3, 1]
print(matrix[matrix > 5])    # 布尔索引后通常不再保留原二维结构

输入特征常用 float32，类别索引和 Embedding 的 token ID 常用 long，掩码常用 bool。整数张量不能直接作为需要梯度的连续参数。torch.empty 分配的内容未初始化，不能把其中的数值当作零。

广播、逐元素乘法与矩阵乘法 ​

广播从末尾对齐形状；对应维度必须相同，或其中一个为 1，缺失的前导轴视为 1。广播通常不真正复制输入数据，但运算结果可能非常大。

python
import torch

x = torch.arange(6, dtype=torch.float32).reshape(2, 3)
bias = torch.tensor([10.0, 20.0, 30.0])
print(x + bias)                      # [2, 3] + [3] -> [2, 3]
print(x * x)                         # 逐元素乘法，仍为 [2, 3]
print((x @ torch.ones(3, 4)).shape)   # 矩阵乘法 -> [2, 4]
print(x.mean(dim=0).shape)            # 跨样本求平均 -> [3]
print(x.mean(dim=1, keepdim=True).shape)  # 每行一个均值 -> [2, 1]

prediction = torch.randn(5, 1)
target = torch.randn(5)
print((prediction - target).shape)   # [5, 5]，并非预期的逐样本误差
assert prediction.shape == target.unsqueeze(1).shape

最后一个例子尤其危险：程序可能不报错，但每个预测与所有标签都发生了比较。回归损失之前应显式检查预测与目标形状一致。

变形不等于交换轴 ​

python
import torch

x = torch.arange(24).reshape(2, 3, 4)
y = x.permute(0, 2, 1)
print(y.shape, y.is_contiguous())    # [2, 4, 3]，通常不连续
print(y.reshape(2, 12).shape)        # 必要时复制存储
print(y.contiguous().view(2, 12).shape)
print(torch.cat([x, x], dim=0).shape)    # [4, 3, 4]，连接已有轴
print(torch.stack([x, x], dim=0).shape)  # [2, 2, 3, 4]，增加新轴
print(x.unsqueeze(1).shape)         # [2, 1, 3, 4]
print(x.flatten(start_dim=1).shape)  # [2, 12]，保留批次
  • reshape 调整元素的形状组织，不会自动把 HWC 图像转换成 CHW；交换轴应使用 permute。
  • view 要求形状与步幅兼容，不保证任何张量都可调用。reshape 在需要时复制，不能依赖它一定共享或一定独立。
  • squeeze() 删除所有长度为 1 的轴，批大小为 1 时可能误删批次；优先指定 squeeze(dim)。
  • expand 通过零步幅扩展可广播维度，多个位置可能指向同一内存；需要独立可写数据时先复制。

共享存储、复制与设备转换 ​

python
import torch

x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
shared = x.detach()          # 不追踪梯度，但仍共享存储
independent = x.detach().clone()
with torch.no_grad():
    x[0] = 99
print(shared.tolist())       # [99.0, 2.0, 3.0]
print(independent.tolist())  # [1.0, 2.0, 3.0]

cpu_copy = x.detach().to("cpu")  # 原本已在 CPU 时可能不复制
print(cpu_copy.device)

clone() 复制数据，但在梯度模式下仍可保留与源张量的求导关系；detach() 切断求导关系，但不复制数据。需要两者时使用 detach().clone()。不要通过 .data 绕开求导系统修改参数。

安装 NumPy 后，CPU 上 torch.from_numpy(array) 通常共享数组存储；torch.tensor(array) 通常复制。导出为 NumPy 常用 tensor.detach().cpu().numpy()，但返回值仍可能与对应 CPU 张量共享内存。

设备转换通常返回结果，不是自动原地迁移：要写 x = x.to(device)。模型和参与同一运算的输入、参数、相关缓冲区应在兼容设备上。记录日志时尽量保留 Python 数值，而不是持续保存 GPU 张量和计算图。

张量自检

能解释每个轴的业务含义；能区分逐元素乘法与矩阵乘法；知道哪些操作可能共享存储；在进入损失函数前检查形状和类型。这四点比背诵所有张量 API 更重要。

自动求导与第一轮参数更新 ​

核心概念

自动求导根据前向运算构建的计算图应用链式法则。反向传播计算梯度，优化器更新参数，两者是不同步骤。梯度不是“新参数”，而是损失对当前参数的局部变化率。

用一个标量手算梯度 ​

设预测为 p = w × x + b，损失为 (p - y)²。当 x=2、y=5、w=1、b=0 时，预测为 2、误差为 -3，因此损失为 9，权重梯度为 2 × (-3) × 2 = -12，偏置梯度为 -6。

python
import torch

w = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
x, target = torch.tensor(2.0), torch.tensor(5.0)
loss = (w * x + b - target).square()
loss.backward()
print(loss.item(), w.grad.item(), b.grad.item())  # 9, -12, -6

with torch.no_grad():
    w -= 0.1 * w.grad
    b -= 0.1 * b.grad
print(w.item(), b.item())  # 约 2.2, 0.6

负梯度说明局部增加参数会降低损失，因此更新规则是“参数减去学习率乘梯度”。学习率过大可能越过低点甚至发散；梯度下降不保证每个 batch 的损失单调下降，也不保证达到全局最优。

叶子张量、梯度累加与图释放 ​

python
import torch

x = torch.tensor(2.0, requires_grad=True)
for _ in range(2):
    loss = x.square()  # 每轮重新前向，产生新图
    loss.backward()
    print(x.grad.item())  # 4，然后 8：梯度默认累加
x.grad = None

middle = x * 3
middle.retain_grad()
middle.square().backward()
print(x.is_leaf, middle.is_leaf)  # True, False
print(x.grad.item(), middle.grad.item())  # 36, 12

由用户直接创建、需要梯度的参数通常是叶子张量；中间结果默认不保存 .grad，调试时可使用 retain_grad()。每次前向一般会重新构图；反向之后会释放为反传保存的中间数据，因此不能随意对同一图反复调用反向传播。

retain_graph=True 保留图以便重复反传，会增加内存占用，不是解决所有报错的开关。create_graph=True 则让导数本身进入新计算图，用于高阶求导：

python
import torch

x = torch.tensor(2.0, requires_grad=True)
y = x ** 3
first = torch.autograd.grad(y, x, create_graph=True)[0]
second = torch.autograd.grad(first, x)[0]
print(first.item(), second.item())  # 12, 12

vector = torch.tensor([1.0, 2.0], requires_grad=True)
(vector.square()).backward(torch.ones_like(vector))
print(vector.grad)  # [2, 4]，对向量输出指定上游梯度

autograd.grad 返回梯度；普通 backward 把梯度累积到叶子张量。向量输出的反向传播需要指定上游梯度，或先通过求和、平均等方式得到标量。

禁用梯度与切换模型状态 ​

操作作用不会做的事情
model.train()启用 Dropout 训练行为、更新 BatchNorm 统计量等不会自动启用梯度
model.eval()切换这些层的推理行为不会自动禁用梯度
torch.no_grad()不记录当前范围内的求导图不会切换 Dropout/BatchNorm
torch.inference_mode()更激进地减少推理追踪开销其产生的张量不适合随意进入后续求导流程
parameter.requires_grad_(False)冻结该参数的梯度计算不会冻结 BatchNorm 运行统计量

评估通常同时使用模型评估状态和无梯度上下文。冻结主干但训练新分类头时，不能把整个前向计算都放进推理上下文，否则分类头也无法求导。

第一份完整训练脚本 ​

下面用带噪声的数据学习 y ≈ 2x + 1。这里的标签与特征确实相关；完全随机的分类标签只能检查程序能否运行，不能证明模型具备学习或泛化能力。

python
import torch
from torch import nn

torch.manual_seed(7)
x = torch.linspace(-2, 2, 200).unsqueeze(1)
y = 2 * x + 1 + 0.05 * torch.randn_like(x)
model = nn.Linear(1, 1)
criterion = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

model.train()
for epoch in range(100):
    optimizer.zero_grad(set_to_none=True)
    prediction = model(x)
    loss = criterion(prediction, y)
    loss.backward()
    optimizer.step()
    if (epoch + 1) % 25 == 0:
        print(epoch + 1, round(loss.item(), 6))

model.eval()
with torch.inference_mode():
    result = model(torch.tensor([[3.0]]))
print("权重、偏置:", model.weight.item(), model.bias.item())
print("输入 3 的预测:", result.item())

权重应接近 2、偏置接近 1，输入 3 的输出接近 7；不要要求浮点结果逐位相等。此例用于理解训练机制，尚未进行独立数据评估，完整项目会加入划分、验证、保存与重新加载。

常见断图行为

把损失转换成 .item() 后再反传、用 torch.tensor(existing_tensor) 重新包装已有结果、转成 NumPy 做中间运算，都会使原有梯度路径中断。.item() 应用于记录日志，而不是代替参与训练的张量损失。

网络模块、损失函数与优化器 ​

核心概念

网络定义可学习的函数，损失定义“怎样算错”，优化器定义“如何更新”。三者必须围绕同一种任务设计；不是任意模型、任意标签和任意损失都能自由组合。

模块与参数注册 ​

python
import torch
from torch import nn

class MLP(nn.Module):
    def __init__(self, input_dim=4, hidden_dim=16, classes=3):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Dropout(0.2),
            nn.Linear(hidden_dim, classes),
        )
        self.register_buffer("input_scale", torch.ones(input_dim))

    def forward(self, x):
        return self.layers(x / self.input_scale)

model = MLP()
output = model(torch.randn(5, 4))
print(output.shape)  # [5, 3]
print("可训练参数数:", sum(p.numel() for p in model.parameters()))
print("状态字典:", list(model.state_dict()))
  • 先调用父类初始化，再把子层绑定为实例属性，参数才能正确注册。
  • 普通 Python 列表中的子层不会自动作为模块容器注册；使用 ModuleList、ModuleDict 或 Sequential。
  • 自定义可训练张量使用 nn.Parameter；需要随模型迁移和保存、但不被优化器更新的状态使用 register_buffer。
  • 在 forward 里临时创建全连接层会不断重新初始化参数，也可能没有进入优化器；应在初始化阶段创建。
  • 调用 model(x) 而非直接调用 model.forward(x)，以保留模块钩子等机制。

全连接层对最后一个轴进行线性变换。Linear(D, H) 的权重形状是 [H, D]，偏置形状为 [H]。中间加入非线性激活，才能避免多个线性层折叠成一个线性变换。ReLU 简单高效，但长期只接收负值的单元可能失活；GELU 常见于 Transformer，不能只凭名字判断更适合所有任务。

损失函数的形状契约 ​

任务模型输出目标常用损失推理转换
回归浮点 [N, D]同形状浮点值MSE、L1、SmoothL1通常直接使用
二分类一个 logit，[N] 或 [N, 1]同形状浮点 0/1BCEWithLogitsLosssigmoid 后按阈值判断
多标签分类[N, C] 独立 logits同形状多热浮点标签BCEWithLogitsLoss每类独立 sigmoid
单标签多分类[N, C] logitslong [N]，取值 0 到 C-1CrossEntropyLossargmax，需概率时再 softmax
像素分类[N, C, H, W] logitslong [N, H, W]CrossEntropyLoss在类别轴 argmax

这里介绍的是交叉熵最常见的类别索引目标形式；它也支持满足条件的概率目标，但不要把两种约定混在一起。

python
import torch
from torch import nn

binary_logits = torch.tensor([0.0, 2.0, -1.0], requires_grad=True)
binary_target = torch.tensor([0.0, 1.0, 0.0])
binary_loss = nn.BCEWithLogitsLoss()(binary_logits, binary_target)
binary_loss.backward()
print(binary_logits.detach().sigmoid())

class_logits = torch.tensor([[2.0, 0.0, -1.0], [0.0, 3.0, 1.0]])
class_target = torch.tensor([0, 1], dtype=torch.long)
print(nn.CrossEntropyLoss()(class_logits, class_target).item())
print(class_logits.argmax(dim=1))  # [0, 1]

CrossEntropyLoss 已包含 log-softmax 与负对数似然的组合；通常不要先 softmax。BCEWithLogitsLoss 比“手动 sigmoid 再 BCELoss”具有更好的数值稳定性。标签必须与输出形状、类别含义一致，而不只是能成功广播。

优化器、初始化与正则化 ​

优化器思路需要关注
SGD沿负梯度方向更新学习率敏感，可配动量
SGD + momentum结合历史更新方向视觉任务常见，需配学习率计划
Adam使用梯度的一阶、二阶矩估计上手方便，不保证泛化一定更好
AdamW将权重衰减与自适应梯度更新解耦现代网络常用，衰减系数需验证
RMSprop根据梯度平方的移动平均调整步长某些序列或强化学习任务使用

weight_decay 在不同优化器中的实现不能一概叫作同一种 L2 正则；AdamW 的解耦衰减与直接向损失加平方范数不完全等价。Dropout 随机屏蔽激活，权重衰减约束参数，数据增强改变输入分布，它们也不是互相替换的同一操作。

python
import torch
from torch import nn

model = nn.Sequential(nn.Linear(4, 16), nn.ReLU(), nn.Linear(16, 2))
# 这里只对后接 ReLU 的隐藏层演示 Kaiming 初始化。
nn.init.kaiming_normal_(model[0].weight, nonlinearity="relu")
nn.init.zeros_(model[0].bias)
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)

默认初始化是可靠起点，不能不分层类型地对所有权重套同一种规则。更换模型分类头后应重新创建优化器，或显式添加新参数组；旧优化器不会自动发现新参数。

数据集、批处理与预处理 ​

核心概念

Dataset 定义怎样取一条样本，Sampler 定义按什么顺序取，DataLoader 定义怎样组成批次并加载。数据处理的正确性，往往比模型多加一层更重要。

从单条数据到一个 batch ​

python
import torch
from torch.utils.data import Dataset, DataLoader, random_split

class TableDataset(Dataset):
    def __init__(self, features, targets):
        if len(features) != len(targets):
            raise ValueError("特征与标签条数不一致")
        self.features = features.float()
        self.targets = targets.long()

    def __len__(self):
        return len(self.targets)

    def __getitem__(self, index):
        return self.features[index], self.targets[index]

def main():
    generator = torch.Generator().manual_seed(12)
    x = torch.randn(120, 4, generator=generator)
    y = (x[:, 0] + x[:, 1] > 0).long()
    dataset = TableDataset(x, y)
    train, valid = random_split(dataset, [96, 24], generator=generator)
    loader = DataLoader(train, batch_size=16, shuffle=True, num_workers=0)
    features, labels = next(iter(loader))
    print(features.shape, labels.shape)  # [16, 4], [16]
    print(len(train), len(valid), len(loader))  # 96, 24, 6

if __name__ == "__main__":
    main()

映射式 Dataset 实现长度和索引访问；流式数据可用 IterableDataset，但多 worker、多个进程必须自行正确分片，否则会重复读取数据。不要把无限流当作有固定长度的普通数据集使用。

数据划分先于统计拟合 ​

正确顺序：先划分，再仅在训练集拟合统计量，最后把同一变换应用于验证、测试和线上输入。

python
import torch

g = torch.Generator().manual_seed(4)
x = torch.randn(100, 3, generator=g) * torch.tensor([1.0, 10.0, 100.0])
train_x, valid_x = x[:80], x[80:]
mean = train_x.mean(dim=0)
std = train_x.std(dim=0, unbiased=False).clamp_min(1e-6)
train_scaled = (train_x - mean) / std
valid_scaled = (valid_x - mean) / std
print(train_scaled.mean(dim=0))  # 接近 0
print(valid_scaled.shape)

不能用完整数据计算均值、词表、缺失值填充值或特征选择结果后才划分，这会把验证信息泄漏到训练流程。随机划分也不是万能的：

  • 同一用户的多条记录应考虑按用户分组，避免身份特征跨集合泄漏。
  • 时间序列应按时间前后划分；预测未来不能用未来统计量。
  • 类别很不平衡时应分层抽样，保证验证集有足够少数类。
  • 增强后的图片、重复文本和近似副本应跟随原样本一起划分。

自定义批处理与加载性能 ​

默认批处理会堆叠等长张量，不能直接堆叠不同长度的句子。自定义 collate_fn 可以补齐、返回长度和掩码，序列章节与文本项目提供完整实现。

参数作用注意
batch_size每批样本数最后一个 batch 可能更小
shuffle每轮改变训练读取顺序验证通常不需要
drop_last丢弃最后不足一批的样本验证通常必须为 False
num_workersCPU 数据加载子进程数从 0 开始排错，再基准测试
pin_memory分配页锁定 CPU 内存常用于 CPU 到 CUDA 传输，不是把数据放进显存
persistent_workers跨 epoch 保留 worker仅在 worker 数大于 0 时启用
prefetch_factor每 worker 预取批次数增大会提高主存占用，需配合多 worker

Windows 多进程启动需要主入口保护；Dataset 和批处理函数尽量定义在模块顶层，不要用局部函数或 lambda 充当多进程可序列化对象。Notebook 中先用 num_workers=0。worker 通常返回 CPU 张量，由主训练进程把 batch 搬到 GPU；不要让每个 worker 初始化 CUDA。

增强和验证不是同一条管线

训练可以随机裁剪、翻转，验证应该使用稳定变换。若两份 Subset 指向同一个底层 Dataset，修改其 transform 会同时影响两者；应分别建立 Dataset 实例，再应用各自索引。

训练、验证、指标与泛化 ​

核心概念

训练集用于更新参数，验证集用于选择模型与超参数，测试集用于最终评估。训练损失下降只能证明拟合训练数据变好，不等于泛化能力提高。

可复用的分类循环 ​

以下代码独立生成线性可分的二分类数据，展示训练、验证与按样本加权汇总。交叉熵使用默认的逐样本平均，故乘以当前批次样本数后再累计。

python
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

def run_epoch(model, loader, device, optimizer=None):
    training = optimizer is not None
    model.train(training)
    total_loss = correct = count = 0
    with torch.set_grad_enabled(training):
        for x, y in loader:
            x, y = x.to(device), y.to(device)
            if training:
                optimizer.zero_grad(set_to_none=True)
            logits = model(x)
            loss = nn.functional.cross_entropy(logits, y)
            if training:
                loss.backward()
                optimizer.step()
            n = y.size(0)
            total_loss += loss.detach().item() * n
            correct += (logits.argmax(1) == y).sum().item()
            count += n
    if count == 0:
        raise ValueError("数据加载器为空")
    return total_loss / count, correct / count

torch.manual_seed(5)
x = torch.randn(1000, 4)
y = (x[:, 0] - 0.5 * x[:, 1] > 0).long()
train_loader = DataLoader(TensorDataset(x[:800], y[:800]), 32, shuffle=True)
valid_loader = DataLoader(TensorDataset(x[800:], y[800:]), 64)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = nn.Sequential(nn.Linear(4, 16), nn.ReLU(), nn.Linear(16, 2)).to(device)
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)
for epoch in range(10):
    train_metrics = run_epoch(model, train_loader, device, optimizer)
    valid_metrics = run_epoch(model, valid_loader, device)
    print(epoch + 1, "train", train_metrics, "valid", valid_metrics)

日志中的训练指标来自一轮中不断变化的模型，不是“最终模型重新完整评估训练集”的指标。比较两者时要注意这一点，也要注意训练时 Dropout 和随机增强的影响。

不要只盯着 accuracy ​

二分类中 TP 是正确预测的正类，FP 是误报，FN 是漏报。precision = TP / (TP + FP)，recall = TP / (TP + FN)，F1 为两者调和平均。分母为零时应明确处理策略，而非传播 NaN。

  • 99% 样本为负类时，全部预测负类也有 99% accuracy，但正类 recall 为 0。
  • 宏平均分别计算每类指标再平均；微平均先累加统计量；加权平均受类别频率影响。
  • 多标签任务阈值不必等于 0.5，但必须在验证集上选择，不能反复调测试集。
  • AUC 衡量排序能力，不能直接替代某个阈值下的精确率、召回率或校准程度。
  • 回归常报告 MAE、RMSE；RMSE 是全体平方误差平均后开根号，不能直接平均每个 batch 的 RMSE。
  • 序列任务的损失分母可能是有效 token 数，不是 batch 样本数；忽略 padding 后应同步修正统计口径。

识别欠拟合、过拟合与数据问题 ​

现象优先排查后续动作
训练与验证都差标签映射、输入范围、损失契约、参数是否更新提高容量、调整学习率、训练更久
训练好、验证差数据分布与重复样本、划分策略正则化、增强、早停、更多数据
损失剧烈波动学习率过大、异常值、小 batch降学习率、处理异常、梯度裁剪
验证离奇地好数据泄漏、验证集过小、目标信息混入特征重新设计划分和特征
分类预测全部相同不平衡、标签错误、激活饱和查看混淆矩阵与各类样本

先尝试让模型过拟合 16 ～ 64 条固定样本：禁用强增强和过强正则，确认损失可以显著下降。如果连小样本都学不会，先修流程，不要立即购买更大的 GPU。

调度器与早停 ​

普通按 epoch 调度器通常在该轮优化更新之后调用；OneCycleLR 等需要按更新步调用。ReduceLROnPlateau 接收验证指标，并与“指标越小/越大越好”的方向一致。早停关注验证集，无改善达到耐心值时结束；应重新加载最佳检查点，而不是直接用最后一轮。

训练验收

至少记录训练/验证损失、主要指标、学习率、耗时和数据版本。固定测试集，报告选择模型的方法；不能只展示一张下降曲线或单个最好数字。

检查点、恢复训练与可复现性 ​

核心概念

推理权重只解决“能否计算预测”，训练检查点还要解决“从哪个训练状态继续”。模型结构、预处理、类别映射、配置和版本同样是实验产物的一部分。

保存的是什么 ​

state_dict() 包含参数与持久 buffer，例如 BatchNorm 的统计量，不包含模型类定义。直接保存整个 Python 模型对象会绑定代码结构且涉及反序列化风险，优先保存状态字典和基础类型配置。

best_state = model.state_dict() 不是冻结快照，其中张量可能继续随模型更新。应使用深复制，或当场写入检查点文件。最佳推理模型和最新恢复检查点可以是两个不同文件。

完整的 epoch 边界恢复示例 ​

此例创建并覆盖 resume_demo.pt。先训练两轮，保存状态，再重建对象并继续一轮。为便于解释，采用 CPU、单进程加载器；“保存后恢复”必须包含独立对象重建，不能只保存不验证加载。

python
import random
from pathlib import Path
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

SEED = 21
random.seed(SEED)
torch.manual_seed(SEED)
x = torch.randn(128, 2)
y = (x[:, :1] * 2 - x[:, 1:] * 3)
generator = torch.Generator().manual_seed(SEED)
loader = DataLoader(TensorDataset(x, y), 16, shuffle=True, generator=generator)

def build():
    model = nn.Sequential(nn.Linear(2, 8), nn.ReLU(), nn.Linear(8, 1))
    optimizer = torch.optim.AdamW(model.parameters(), lr=0.01)
    scheduler = torch.optim.lr_scheduler.StepLR(optimizer, step_size=2, gamma=0.5)
    return model, optimizer, scheduler

def train_epoch(model, optimizer):
    model.train()
    total = 0.0
    for xb, yb in loader:
        optimizer.zero_grad(set_to_none=True)
        loss = nn.functional.mse_loss(model(xb), yb)
        loss.backward()
        optimizer.step()
        total += loss.item() * len(xb)
    return total / len(loader.dataset)

model, optimizer, scheduler = build()
for epoch in range(2):
    print("before", epoch, train_epoch(model, optimizer))
    scheduler.step()

path = Path("resume_demo.pt")
torch.save({
    "epoch": epoch,
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
    "scheduler": scheduler.state_dict(),
    "torch_rng": torch.get_rng_state(),
    "python_rng": random.getstate(),
    "loader_rng": generator.get_state(),
    "config": {"seed": SEED, "input_dim": 2},
}, path)

# 创建对象会消耗随机数，所以应在创建和加载结束后恢复 RNG。
restored, restored_optimizer, restored_scheduler = build()
checkpoint = torch.load(path, map_location="cpu", weights_only=True)
restored.load_state_dict(checkpoint["model"])
restored_optimizer.load_state_dict(checkpoint["optimizer"])
restored_scheduler.load_state_dict(checkpoint["scheduler"])
torch.set_rng_state(checkpoint["torch_rng"])
random.setstate(checkpoint["python_rng"])
generator.set_state(checkpoint["loader_rng"])
start_epoch = checkpoint["epoch"] + 1
print("resumed", start_epoch, train_epoch(restored, restored_optimizer))
restored_scheduler.step()

这里先创建调度器，再加载优化器和调度器状态，避免初始化顺序覆盖已恢复学习率。实际工程还需要保存：

  • 最佳验证指标、早停计数、全局更新步与数据划分索引。
  • 使用 CUDA 时的 torch.cuda.get_rng_state_all()，恢复时使用对应设备的状态。
  • 使用 AMP 时的 GradScaler 状态；使用 NumPy 随机数时的相应状态。
  • 词表、类别顺序、特征标准化统计、配置和代码/依赖版本。

跨设备加载时先确定目标设备再构建优化器，核验其状态张量设备；不要以为 map_location 自动修正所有自定义训练状态。多卡恢复通常需要每个 rank 的 RNG/采样状态，不能只保存 rank 0 的随机状态就宣称完全可复现。

安全与精确恢复边界

仅加载可信来源模型。显式使用 weights_only=True 可缩小可执行反序列化范围，但不是处理任意不可信文件的沙箱；仍需校验来源、大小和完整性，不要为消除报错直接切换不安全加载模式。中途恢复一个 epoch 还涉及采样游标、worker 预取、增强 RNG、尚未更新的梯度等，本示例只承诺 epoch 边界的恢复机制。

可复现不等于只设一个 seed ​

可复现至少包含固定数据、固定随机源、固定版本与硬件条件。某些并行算法本身非确定性，跨 PyTorch 版本、CPU/GPU 或不同硬件不保证逐位一致。

确定性模式可能降低性能或直接报告不支持的算子。某些 CUDA 运算还要求在进程启动、CUDA 初始化之前设置官方文档规定的环境变量。把这些条件记录下来，而不是悄悄关闭检查再声称严格复现。

卷积网络与迁移学习 ​

核心概念

卷积通过局部连接与权重共享提取空间模式。迁移学习复用已有表征，但必须同时匹配输入预处理、任务输出与训练策略。

从图像形状推导网络 ​

PyTorch 二维卷积一般使用 [N, C, H, W]；三通道图像不是 [N, H, W, C]。卷积单轴输出大小为：

text
输出 = floor((输入 + 2 × padding - dilation × (kernel_size - 1) - 1) / stride + 1)
普通卷积权重数 = 输出通道 × 输入通道 × 核高 × 核宽
分组卷积权重数 = 输出通道 × (输入通道 / groups) × 核高 × 核宽
偏置启用时，再加输出通道个参数
python
import torch
from torch import nn

class SmallCNN(nn.Module):
    def __init__(self, classes=10):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 16, 3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 3, padding=1),
            nn.ReLU(),
            nn.AdaptiveAvgPool2d(1),
        )
        self.head = nn.Linear(32, classes)

    def forward(self, x):
        return self.head(self.features(x).flatten(1))

model = SmallCNN()
x = torch.randn(8, 1, 28, 28)
print(model.features(x).shape)  # [8, 32, 1, 1]
print(model(x).shape)  # [8, 10]

池化减少空间分辨率，自适应池化把不同空间尺寸变成固定输出尺寸；它不会自动解决图像通道数错误。感受野描述某个输出能“看见”的输入区域，多层卷积、步长和扩张率都会影响它。

BatchNorm 在训练时使用批统计并更新运行统计，评估时通常使用运行统计；小 batch 可能不稳定，可考虑 GroupNorm 等替代。残差连接把输入加回变换结果，有助于深层网络优化，但两条分支形状必须兼容，必要时用投影调整通道或步长。

冻结主干与微调 ​

下面需要与 PyTorch 配套的 torchvision；首次运行会下载预训练权重到本机缓存。随机输入只用来验证形状与梯度路径，不是有效训练数据。

python
import torch
from torch import nn
from torchvision.models import resnet18, ResNet18_Weights

weights = ResNet18_Weights.DEFAULT
model = resnet18(weights=weights)
for parameter in model.parameters():
    parameter.requires_grad_(False)
model.fc = nn.Linear(model.fc.in_features, 3)

# 固定主干的 BatchNorm 状态，只训练新的分类头。
model.eval()
model.fc.train()
images = torch.rand(2, 3, 256, 256)

权重自带的 transforms 规定缩放、裁剪和归一化。不能把像素除以 255 后就认为完全匹配预训练输入。

实际训练可先只训练分类头，再解冻最后一组卷积层，用更低学习率微调主干。解冻之后重新创建优化器或添加参数组；若每个 epoch 调用 model.train()，会把冻结主干中的 BatchNorm 也切回训练状态，必须按策略重新固定。冻结参数与冻结运行统计是两回事。

序列模型、Embedding 与变长输入 ​

核心概念

序列不仅有“哪些值”，还有“出现顺序”。Embedding 把离散编号映射为可学习向量，RNN/LSTM/GRU 递归维护状态；padding 是批处理占位，不应当作真实信息。

Token 与 Embedding ​

词表将 token 映射到整数 ID。ID 大小没有语义距离：编号 100 不表示比编号 10 更积极。Embedding 本质上是可训练的查找表，形状 [词表大小, 向量维度]。输入 [N, L] 的 long 索引，输出 [N, L, E]。

常预留 PAD=0、UNK=1；PAD 补齐长度，UNK 处理未见过的词。padding_idx=0 使该行不会从查找操作获得梯度，但并不会自动让后面的平均池化或注意力忽略补齐位置，仍需长度或掩码。

RNN、LSTM 与 GRU 的区别 ​

基础 RNN 递归计算当前输入与前一隐藏状态的组合，长序列容易梯度消失或爆炸。LSTM 引入记忆单元和输入/遗忘/输出门，GRU 用更新门与重置门控制状态，参数通常更少。门控缓解长期依赖问题，但没有消除所有优化困难。

网络状态batch_first=True 时输出最终状态形状
RNNh[N, L, D×H][层数×D, N, H]
GRUh[N, L, D×H][层数×D, N, H]
LSTMh 与 c[N, L, D×H]h、c 通常均为 [层数×D, N, H]

D 为方向数，双向为 2；此表不讨论带投影 LSTM。batch_first 只改变输入/输出序列的轴顺序，不改变最终隐藏状态的轴顺序。多层 RNN 的 dropout 通常用于层与层之间，只有一层时不能期待它自动实现同样的层间随机丢弃。

变长序列打包 ​

以下脚本同时处理补齐与双向 GRU 的最后状态，避免误用 output[:, -1] 取到 padding 的输出。

python
import torch
from torch import nn
from torch.nn.utils.rnn import pad_sequence, pack_padded_sequence

sequences = [torch.tensor([2, 3, 4]), torch.tensor([5]), torch.tensor([6, 7])]
lengths = torch.tensor([len(seq) for seq in sequences], dtype=torch.long)
tokens = pad_sequence(sequences, batch_first=True, padding_value=0)
embedding = nn.Embedding(10, 8, padding_idx=0)
gru = nn.GRU(8, 12, batch_first=True, bidirectional=True)
head = nn.Linear(24, 2)

embedded = embedding(tokens)
packed = pack_padded_sequence(
    embedded, lengths.cpu(), batch_first=True, enforce_sorted=False,
)
_, hidden = gru(packed)
# 单层双向：第 0 个是正向最终状态，第 1 个是反向最终状态。
representation = torch.cat([hidden[-2], hidden[-1]], dim=1)
logits = head(representation)
loss = nn.functional.cross_entropy(logits, torch.tensor([0, 1, 0]))
loss.backward()
print(tokens.shape, logits.shape)  # [3, 3], [3, 2]

打包长度必须为正，空文本可映射为一个 UNK；长度张量传入打包函数时保留在 CPU。enforce_sorted=False 允许不按长度降序排列，返回的最终隐藏状态会对应原样本顺序。多层双向模型可将隐藏状态理解为“层、方向、batch、hidden”，明确选取最后一层两个方向。

状态延续与截断反传 ​

独立句子的 batch 通常不应继承上一批状态；否则会把不相关样本串联起来。对连续长流做截断反向传播时，可以将上一片段状态传给下一片段，但片段边界需要 detach；LSTM 的 h 与 c 都要处理。双向模型使用未来上下文，不适合直接用作严格在线、只能看到过去的预测器。

注意力与 Transformer ​

核心概念

注意力根据内容建立 token 间联系。Transformer 用注意力、前馈网络、残差和归一化组成层；位置信息与掩码决定模型是否知道顺序、是否偷看未来。

从 Q、K、V 理解注意力 ​

输入分别投影为 Query、Key、Value。Query 与 Key 点积衡量匹配程度，除以键维度平方根防止尺度过大，再归一化成权重，加权汇总 Value。

text
Q: [N, heads, Lq, d]     K: [N, heads, Lk, d]
Q × K转置 -> [N, heads, Lq, Lk]
加掩码 -> softmax -> 权重 × V -> [N, heads, Lq, value_dim]

自注意力的 Q/K/V 来自同一序列；交叉注意力的 Q 来自目标序列，K/V 来自另一序列，例如编码器输出。多头注意力将特征分到多个子空间，一般要求模型维度能被头数整除。

python
import math
import torch

torch.manual_seed(1)
x = torch.randn(2, 4, 8)
q, k, v = x, x, x  # 教学用：省略可学习投影
scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
future = torch.ones(4, 4, dtype=torch.bool).triu(1)
scores = scores.masked_fill(future, float("-inf"))
attention = scores.softmax(dim=-1)
output = attention @ v
print(output.shape)  # [2, 4, 8]
print(attention[0, 0])  # 第一位置只能关注自身

普通密集自注意力的分数矩阵随序列长度平方增长。高效内核可降低中间存储和提高吞吐，但不能因此宣称任意长度输入都没有计算或内存成本。

带 padding 掩码的编码器分类 ​

下面使用学习式位置向量，输出句子分类 logits。padding 掩码阻止真实 token 把补齐位置当作 key；最后的池化仍需要单独排除补齐位置。

python
import torch
from torch import nn

class EncoderClassifier(nn.Module):
    def __init__(self, vocab_size=100, dim=32, max_length=64):
        super().__init__()
        self.max_length = max_length
        self.token = nn.Embedding(vocab_size, dim, padding_idx=0)
        self.position = nn.Embedding(max_length, dim)
        layer = nn.TransformerEncoderLayer(
            d_model=dim, nhead=4, dim_feedforward=64,
            dropout=0.1, batch_first=True,
        )
        self.encoder = nn.TransformerEncoder(layer, num_layers=2)
        # 克隆层初始数值相同；这里重新初始化各层的矩阵权重。
        for block in self.encoder.layers:
            for parameter in block.parameters():
                if parameter.dim() > 1:
                    nn.init.xavier_uniform_(parameter)
        self.head = nn.Linear(dim, 2)

    def forward(self, ids):
        if ids.size(1) > self.max_length:
            raise ValueError("输入超过最大长度")
        padding = ids.eq(0)
        if padding.all(dim=1).any():
            raise ValueError("每个句子至少要有一个有效 token")
        positions = torch.arange(ids.size(1), device=ids.device)
        x = self.token(ids) + self.position(positions).unsqueeze(0)
        x = self.encoder(x, src_key_padding_mask=padding)
        valid = (~padding).unsqueeze(-1)
        pooled = (x * valid).sum(1) / valid.sum(1).clamp_min(1)
        return self.head(pooled)

model = EncoderClassifier()
ids = torch.tensor([[2, 3, 4, 0], [5, 6, 0, 0]])
logits = model(ids)
nn.functional.cross_entropy(logits, torch.tensor([0, 1])).backward()
print(logits.shape)  # [2, 2]

没有位置编码的自注意力本身不能表达同样的顺序信息。句子分类允许双向上下文；语言生成则需要因果掩码。位置上限也是部署契约的一部分，必须在训练与推理时采用一致的截断规则。

不同 API 的布尔掩码语义并不相同

MultiheadAttention 和 Transformer 的布尔屏蔽掩码中，True 通常表示禁止关注；functional.scaled_dot_product_attention 的布尔 attention mask 中，True 表示允许参与。迁移实现时必须检查所用 API。不要把某一行全部屏蔽后仍期待 softmax 得到有效概率。

编码、生成与训练目标 ​

编码器适合分类、表示提取；自回归解码器用前缀预测下一个 token；编码器—解码器适合翻译等输入到输出的条件生成。生成训练常把同一序列错开一位作为输入和目标，并忽略 PAD 的损失。推理阶段逐 token 生成，可以缓存历史 K/V 减少重复计算，但缓存要按会话隔离并预算显存。

训练损失低并不意味着生成内容一定正确。微调大模型前，先掌握 tokenizer、特殊 token、截断、label mask 和验证集设计，再引入参数高效微调或大规模分布式。

混合精度、梯度累积与性能分析 ​

核心概念

优化性能之前先定义指标：单批延迟、每秒样本数、峰值显存或端到端耗时。混合精度降低部分运算精度，梯度累积减少一次前向的样本数，它们解决的是不同问题。

自动混合精度不是整个模型转半精度 ​

autocast 根据算子选择适当精度，通常保留模型参数的常规浮点存储；GradScaler 放大损失来减轻 FP16 梯度下溢，并在检测到非有限梯度时跳过更新。不要把输入、模型、标签全部无差别转成 half；类别索引仍然必须是整数。

  • CUDA FP16 通常搭配梯度缩放。
  • BF16 指数范围更大，通常不需要缩放，但要求相应设备与算子支持。
  • CPU autocast 常使用 BF16；是否更快取决于硬件和工作负载。
  • MPS、CPU、CUDA 的精度支持不能一概而论；先验证普通精度基线。

正确处理最后一组梯度累积 ​

把每个 micro-batch 的平均 loss 固定除以累积步数，在最后不足一组或批大小不一致时会改变样本权重。下面对每批使用损失总和，累积后按该组实际样本数归一化；裁剪发生在取消缩放与归一化之后。

python
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

torch.manual_seed(6)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
use_amp = device.type == "cuda"
x = torch.randn(103, 4)
y = (x[:, 0] > 0).long()
loader = DataLoader(TensorDataset(x, y), batch_size=16, shuffle=True)
model = nn.Sequential(nn.Linear(4, 16), nn.ReLU(), nn.Linear(16, 2)).to(device)
optimizer = torch.optim.AdamW(model.parameters(), lr=0.01)
scaler = torch.amp.GradScaler("cuda", enabled=use_amp)
accumulation_steps = 3

for epoch in range(3):
    model.train()
    optimizer.zero_grad(set_to_none=True)
    group_samples = 0
    for index, (xb, yb) in enumerate(loader):
        xb, yb = xb.to(device), yb.to(device)
        with torch.autocast(device_type=device.type, dtype=torch.float16, enabled=use_amp):
            logits = model(xb)
            loss_sum = nn.functional.cross_entropy(logits, yb, reduction="sum")
        scaler.scale(loss_sum).backward()
        group_samples += len(yb)
        boundary = (index + 1) % accumulation_steps == 0
        if boundary or index + 1 == len(loader):
            scaler.unscale_(optimizer)
            for parameter in model.parameters():
                if parameter.grad is not None:
                    parameter.grad.div_(group_samples)
            nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
            scaler.step(optimizer)
            scaler.update()
            optimizer.zero_grad(set_to_none=True)
            group_samples = 0
    print("epoch", epoch + 1, "scale", scaler.get_scale())

这与一次大 batch 的样本平均梯度相对应，但不保证数值完全相同：BatchNorm 的统计按 micro-batch 计算，Dropout 的随机性及浮点求和顺序也不同。加权损失或忽略 token 的任务，应按真实损失分母归一化；不能继续机械使用样本数。

调度器应跟随真实优化器更新，而不是每个 micro-batch 更新一次；AMP 因溢出跳过更新时，还要避免调度器错误前进。梯度累积中只能在一组结束时调用一次取消缩放，不能每个 micro-batch 都调用。

定位瓶颈的顺序 ​

text
先确认正确性 -> 固定代表性输入 -> 预热 -> 测量基线
        -> 判断 CPU / 数据读取 / 传输 / GPU 运算瓶颈
        -> 一次只改变一个因素 -> 比较速度、显存与指标

GPU 运算异步提交，直接用 CPU 时钟包围前向可能只测到提交时间。CUDA 基准需要适当同步或 CUDA Event；不要为测量而在正式训练的每个算子后都同步。.item()、频繁打印 GPU 值和来回搬运设备数据也可能触发同步。

常见优化与代价 ​

方案适用条件代价或边界
增大 batchGPU 利用率低且显存足够可能影响收敛，需重新评估学习率
多 worker / 预取数据准备成为瓶颈主存、进程启动与 I/O 竞争
pin_memory + non_blockingCPU 到 CUDA 传输真正重叠还依赖调度等条件

activation checkpoint 新代码应明确 use_reentrant=False 等版本相关选项，并注意重算中的随机性或副作用。empty_cache() 释放未使用的缓存块给其他程序，不会释放仍被张量引用的显存，也不是修复训练内存泄漏的常规办法。

多卡训练与分布式数据并行 ​

核心概念

DDP 通常采用一张 GPU 对应一个进程：各进程保存完整模型，处理不同数据，反传时同步梯度。它不是自动把一个超大模型拆到多张卡上。

进程、设备和数据之间的关系 ​

rank 是全局进程编号，local rank 是当前机器内编号，world size 是总进程数。单机两卡通常启动两个进程；每个进程绑定自己的设备，使用 DistributedSampler 读取不同训练片段。

下面是独立脚本，保存为 ddp_demo.py。运行条件为 Linux、至少两张可用 NVIDIA GPU、支持 NCCL 的 PyTorch 构建；不把它当作 Windows 原生两卡通用示例。

python
import os
import torch
import torch.distributed as dist
from torch import nn
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data import DataLoader, TensorDataset, DistributedSampler

def main():
    local_rank = int(os.environ["LOCAL_RANK"])
    torch.cuda.set_device(local_rank)
    dist.init_process_group(backend="nccl")
    try:
        rank = dist.get_rank()
        world = dist.get_world_size()
        device = torch.device("cuda", local_rank)
        torch.manual_seed(8)
        x = torch.randn(1024, 4)
        y = (x[:, 0] + x[:, 1] > 0).long()
        train = TensorDataset(x[:800], y[:800])
        valid = TensorDataset(x[800:], y[800:])
        sampler = DistributedSampler(train, shuffle=True)
        loader = DataLoader(train, batch_size=32, sampler=sampler, num_workers=0)
        model = DDP(nn.Linear(4, 2).to(device), device_ids=[local_rank])
        optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
        for epoch in range(5):
            sampler.set_epoch(epoch)
            model.train()
            for xb, yb in loader:
                xb, yb = xb.to(device), yb.to(device)
                optimizer.zero_grad(set_to_none=True)
                loss = nn.functional.cross_entropy(model(xb), yb)
                loss.backward()
                optimizer.step()

            # 验证按 rank 无重复分片，允许各进程批次数不同。
            indices = list(range(rank, len(valid), world))
            validation = DataLoader(torch.utils.data.Subset(valid, indices), batch_size=64)
            model.eval()
            totals = torch.zeros(3, dtype=torch.float64, device=device)
            with torch.inference_mode():
                for xb, yb in validation:
                    xb, yb = xb.to(device), yb.to(device)
                    # 此模型无 buffer/自定义通信；绕过 DDP 的前向同步。
                    logits = model.module(xb)
                    totals[0] += nn.functional.cross_entropy(logits, yb, reduction="sum")
                    totals[1] += (logits.argmax(1) == yb).sum()
                    totals[2] += len(yb)
            dist.all_reduce(totals, op=dist.ReduceOp.SUM)
            if rank == 0:
                print(epoch, "loss", (totals[0] / totals[2]).item(),
                      "accuracy", (totals[1] / totals[2]).item())
        if rank == 0:
            torch.save(model.module.state_dict(), "ddp_weights.pt")
        dist.barrier()
    finally:
        dist.destroy_process_group()

if __name__ == "__main__":
    main()

训练 sampler 可能为对齐进程长度补重复样本；验证若直接使用同样补齐策略，结果可能有偏。此例验证手动无重复分片并汇总损失总和、正确数、样本数，而不是平均各 rank 的准确率。

同步协议必须一致

所有 rank 必须以一致顺序参加 collective 通信；不能只有 rank 0 调用 all_reduce。含 BatchNorm buffer 或自定义 collective 的模型不能不加分析地照搬这里的不等长验证循环，应先同步模型状态并设计验证通信。仅 rank 0 验证时也应避免调用需要其他 rank 配合的 DDP 前向。

扩展与常见误区 ​

  • 每个 rank 的 batch 为 B，进程数 W、累积步数 K 时，常规完整组的有效 batch 为 B×W×K；不要未经验证就线性放大学习率。
  • 每轮调用 sampler 的 set_epoch，否则打乱顺序可能每轮相同；不能同时给 DataLoader 设置 sampler 与 shuffle=True。
  • 梯度累积可用 no_sync 暂停非边界批次的同步，且前向也应放进该上下文；最后一批仍须同步。不同 rank 的有效样本数不等时，平均梯度的权重必须另行推导。
  • DDP 不自动同步完整数据集指标，也不自动提供可恢复的数据游标。
  • 一张卡放不下模型时，可进一步研究 FSDP、张量并行、流水线并行或参数高效训练；这些并非把 DDP 开关改一下即可解决。
  • 通信卡住时先检查所有 rank 的异常日志、设备绑定和 collective 次序，再检查网络、端口和 NCCL 环境。

自定义损失与梯度验证 ​

下面实现带阈值的平滑绝对误差，所有运算由原生算子构成，因此自动求导可以直接工作。

python
import torch
from torch import nn

class HuberLikeLoss(nn.Module):
    def __init__(self, delta=1.0):
        super().__init__()
        if delta <= 0:
            raise ValueError("delta 必须为正数")
        self.delta = delta

    def forward(self, prediction, target):
        if prediction.shape != target.shape:
            raise ValueError("预测与目标形状必须一致")
        error = (prediction - target).abs()
        quadratic = 0.5 * error.square()
        linear = self.delta * (error - 0.5 * self.delta)
        return torch.where(error <= self.delta, quadratic, linear).mean()

prediction = torch.tensor([0.3, 2.5], dtype=torch.double, requires_grad=True)
target = torch.zeros_like(prediction)
criterion = HuberLikeLoss()
print(torch.autograd.gradcheck(lambda value: criterion(value, target), (prediction,)))
criterion(prediction, target).backward()
print(prediction.grad)

gradcheck 用数值差分与解析梯度比较，通常使用双精度、远离不可导拐点的小输入。它不是性能测试，也不能证明全部输入都正确。

自定义反向规则 ​

python
import torch

class Square(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)
        return x.square()

    @staticmethod
    def backward(ctx, grad_output):
        (x,) = ctx.saved_tensors
        return grad_output * 2 * x

x = torch.tensor([0.2, -0.7], dtype=torch.double, requires_grad=True)
print(torch.autograd.gradcheck(Square.apply, (x,)))
print(torch.autograd.gradgradcheck(Square.apply, (x,)))
Square.apply(x).sum().backward()
print(x.grad)

反向返回的梯度数量和顺序要与前向输入对应；非张量或不求导参数通常对应 None。上例用于教学，实际平方应使用原生算子。涉及原地修改、非可导输出、二阶导数或外部 CUDA 运算时，要分别处理框架协议，不能只写出一阶公式就认为组件通用。

多任务网络与损失尺度 ​

共享主干可以同时输出类别和连续值，但两个损失的数值尺度可能差别很大。损失权重应依据业务目标、尺度和验证结果设定，不能把不同量纲的损失相加后只看总值。

python
import torch
from torch import nn

class MultiTask(nn.Module):
    def __init__(self):
        super().__init__()
        self.backbone = nn.Sequential(nn.Linear(4, 16), nn.ReLU())
        self.classifier = nn.Linear(16, 2)
        self.regressor = nn.Linear(16, 1)

    def forward(self, x):
        hidden = self.backbone(x)
        return self.classifier(hidden), self.regressor(hidden)

x = torch.randn(16, 4)
labels = (x[:, 0] > 0).long()
values = x[:, :1] + x[:, 1:2]
model = MultiTask()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)
optimizer.zero_grad(set_to_none=True)
logits, prediction = model(x)
classification = nn.functional.cross_entropy(logits, labels)
regression = nn.functional.mse_loss(prediction, values)
loss = classification + 0.2 * regression
loss.backward()
optimizer.step()
print(classification.item(), regression.item())

知识蒸馏 ​

教师的软分布包含类别间相对关系，学生结合真实标签和教师分布学习。教师应使用已训练好的可信权重并设为评估状态。下面的随机教师仅验证一次计算路径，不能证明蒸馏有效。

python
import torch
from torch import nn
from torch.nn import functional as F

teacher = nn.Sequential(nn.Linear(4, 32), nn.ReLU(), nn.Linear(32, 3)).eval()
student = nn.Linear(4, 3)
for parameter in teacher.parameters():
    parameter.requires_grad_(False)
x, labels = torch.randn(12, 4), torch.arange(12) % 3
temperature, alpha = 3.0, 0.5
optimizer = torch.optim.AdamW(student.parameters(), lr=1e-3)
with torch.no_grad():
    teacher_logits = teacher(x)
student_logits = student(x)
hard_loss = F.cross_entropy(student_logits, labels)
soft_loss = F.kl_div(
    F.log_softmax(student_logits / temperature, dim=1),
    F.softmax(teacher_logits / temperature, dim=1),
    reduction="batchmean",
) * temperature ** 2
loss = (1 - alpha) * hard_loss + alpha * soft_loss
optimizer.zero_grad(set_to_none=True)
loss.backward()
optimizer.step()
print(loss.item())

这里 KL 接口的输入是学生的对数概率，目标是教师概率；不能把两个普通 softmax 直接传进去。温度平方用于补偿温度对梯度尺度的影响。需要比较学生独立训练与蒸馏训练的验证结果、延迟和模型大小。

ONNX 与上线验收 ​

当前 PyTorch ONNX 路线可使用 torch.onnx.export(..., dynamo=True)，通常需要配套 onnx、onnxscript 等依赖。具体参数随版本演进，先固定导出器和目标运行时版本，再选择 opset 与动态维度。不要仅凭“导出命令未报错”就宣布部署成功。

上线前至少检查：

  1. 在目标运行时重新加载，使用代表性数据比较输出误差与最终指标。
  2. 对输入形状、类型、长度、图像通道和取值范围做校验；复用训练预处理。
  3. 保存词表/类别顺序、归一化统计、阈值、模型版本和依赖清单。
  4. 推理使用评估状态与无梯度上下文，预热后测量吞吐及 P50/P95 延迟。
  5. 限制 batch、队列、并发与超时；GPU 服务的多个进程通常各有模型副本，需要预算显存。
  6. 为模型更新提供灰度、回滚、漂移监控与错误日志，不记录无必要的敏感输入。

量化能减少存储与部分硬件上的计算成本，但需要校准或训练、算子支持和目标运行时配合。量化后的任务指标、冷启动和真实延迟应重新测量，不能仅以文件变小作为成功标准。

项目一：结构化数据回归 ​

核心概念

用可控合成数据学习完整回归工程：先划分，再拟合标准化，训练时选择最佳验证模型，最后在独立测试集评价并重载推理。合成数据用于验证流程，不代表真实房价预测能力。

目标与数据 ​

输入为面积、房龄、到市中心距离，输出为模拟价格。数据包含线性关系与随机噪声，因此可以检查模型是否超过“始终预测训练均价”的基线。输出价格单位由生成公式定义，并非真实货币报价。

仅依赖 PyTorch；默认 CPU，可加 --device cuda。将下面完整代码保存为 regression_project.py。运行会创建输出目录并覆盖同名最佳检查点，输入端不会读写真实业务数据。

完整脚本 ​

python
import argparse
from pathlib import Path
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

class Regressor(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(3, 32), nn.ReLU(), nn.Linear(32, 1))

    def forward(self, x):
        return self.net(x)

@torch.inference_mode()
def evaluate(model, x, y, device, y_mean, y_std):
    model.eval()
    predicted = model(x.to(device)).cpu() * y_std + y_mean
    difference = predicted - y
    return difference.abs().mean().item(), difference.square().mean().sqrt().item()

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--epochs", type=int, default=100)
    parser.add_argument("--device", default="cpu", choices=["cpu", "cuda"])
    parser.add_argument("--output", type=Path, default=Path("runs/regression"))
    args = parser.parse_args()
    if args.epochs < 1:
        parser.error("epochs 必须大于 0")
    if args.device == "cuda" and not torch.cuda.is_available():
        parser.error("当前环境无法使用 CUDA")
    torch.manual_seed(42)
    device = torch.device(args.device)
    args.output.mkdir(parents=True, exist_ok=True)
    checkpoint_path = args.output / "best.pt"

    g = torch.Generator().manual_seed(42)
    raw = torch.rand(1200, 3, generator=g)
    x = raw * torch.tensor([170.0, 40.0, 30.0]) + torch.tensor([30.0, 0.0, 0.0])
    y = 3 * x[:, :1] - 2 * x[:, 1:2] - 4 * x[:, 2:3] + 80
    y += 8 * torch.randn(1200, 1, generator=g)
    order = torch.randperm(len(x), generator=g)
    train_id, valid_id, test_id = order[:840], order[840:1020], order[1020:]
    train_x, train_y = x[train_id], y[train_id]
    x_mean = train_x.mean(0)
    x_std = train_x.std(0, unbiased=False).clamp_min(1e-6)
    y_mean = train_y.mean(0)
    y_std = train_y.std(0, unbiased=False).clamp_min(1e-6)
    scaled_x = (x - x_mean) / x_std
    scaled_y = (y - y_mean) / y_std
    loader = DataLoader(
        TensorDataset(scaled_x[train_id], scaled_y[train_id]),
        batch_size=64, shuffle=True,
        generator=torch.Generator().manual_seed(99),
    )
    model = Regressor().to(device)
    optimizer = torch.optim.AdamW(model.parameters(), lr=0.01, weight_decay=1e-4)
    best_rmse = float("inf")
    stale = 0
    for epoch in range(args.epochs):
        model.train()
        train_sum = 0.0
        for xb, yb in loader:
            xb, yb = xb.to(device), yb.to(device)
            optimizer.zero_grad(set_to_none=True)
            loss = nn.functional.mse_loss(model(xb), yb)
            loss.backward()
            optimizer.step()
            train_sum += loss.item() * len(xb)
        mae, rmse = evaluate(model, scaled_x[valid_id], y[valid_id], device, y_mean, y_std)
        if not torch.isfinite(torch.tensor(rmse)):
            raise RuntimeError("验证指标非有限，请检查学习率与数据")
        if rmse < best_rmse:
            best_rmse, stale = rmse, 0
            torch.save({
                "model": model.state_dict(), "x_mean": x_mean, "x_std": x_std,
                "y_mean": y_mean, "y_std": y_std,
                "epoch": epoch + 1, "valid_rmse": rmse,
                "features": ["area", "age", "distance"],
            }, checkpoint_path)
        else:
            stale += 1
        if epoch == 0 or (epoch + 1) % 10 == 0:
            print(f"epoch={epoch + 1} train_mse_scaled={train_sum / len(train_id):.4f} "
                  f"valid_mae={mae:.2f} valid_rmse={rmse:.2f}")
        if stale >= 15:
            print("early stop")
            break

    saved = torch.load(checkpoint_path, map_location="cpu", weights_only=True)
    restored = Regressor()
    restored.load_state_dict(saved["model"])
    restored.eval()
    test_scaled = (x[test_id] - saved["x_mean"]) / saved["x_std"]
    mae, rmse = evaluate(restored, test_scaled, y[test_id], torch.device("cpu"),
                         saved["y_mean"], saved["y_std"])
    baseline = (y[test_id] - train_y.mean()).square().mean().sqrt().item()
    print(f"test_mae={mae:.2f} test_rmse={rmse:.2f} mean_baseline_rmse={baseline:.2f}")
    sample = torch.tensor([[90.0, 5.0, 8.0]])
    with torch.inference_mode():
        result = restored((sample - saved["x_mean"]) / saved["x_std"])
        result = result * saved["y_std"] + saved["y_mean"]
    print("样本预测:", result.item(), "模型路径:", checkpoint_path)

if __name__ == "__main__":
    main()

python
import argparse
from pathlib import Path
import torch
from torch import nn
from torch.utils.data import DataLoader, Subset
from torchvision import datasets, transforms

class FashionCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 16, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        )
        self.head = nn.Sequential(
            nn.Flatten(), nn.Linear(32 * 7 * 7, 64), nn.ReLU(),
            nn.Dropout(0.2), nn.Linear(64, 10),
        )

    def forward(self, x):
        return self.head(self.features(x))

def run_epoch(model, loader, device, optimizer=None):
    training = optimizer is not None
    model.train(training)
    loss_sum = correct = total = 0
    confusion = torch.zeros(10, 10, dtype=torch.long)
    with torch.set_grad_enabled(training):
        for images, labels in loader:
            images = images.to(device, non_blocking=device.type == "cuda")
            labels = labels.to(device, non_blocking=device.type == "cuda")
            if training:
                optimizer.zero_grad(set_to_none=True)
            logits = model(images)
            loss = nn.functional.cross_entropy(logits, labels)
            if training:
                loss.backward()
                optimizer.step()
            predicted = logits.argmax(1)
            loss_sum += loss.detach().item() * len(labels)
            correct += (predicted == labels).sum().item()
            total += len(labels)
            if not training:
                pairs = (labels * 10 + predicted).cpu()
                confusion += torch.bincount(pairs, minlength=100).reshape(10, 10)
    if total == 0:
        raise ValueError("数据集为空")
    return loss_sum / total, correct / total, confusion

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--epochs", type=int, default=5)
    parser.add_argument("--batch-size", type=int, default=128)
    parser.add_argument("--smoke", action="store_true")
    parser.add_argument("--data", type=Path, default=Path("data"))
    parser.add_argument("--output", type=Path, default=Path("runs/fashion"))
    args = parser.parse_args()
    if args.epochs < 1 or args.batch_size < 1:
        parser.error("epochs 和 batch-size 必须为正数")
    torch.manual_seed(42)
    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    args.output.mkdir(parents=True, exist_ok=True)
    best_path = args.output / "best.pt"
    # 固定的中心缩放，不是用验证/测试数据拟合的统计量。
    preprocessing = transforms.Compose([
        transforms.ToTensor(), transforms.Normalize((0.5,), (0.5,)),
    ])
    full_train = datasets.FashionMNIST(args.data, train=True, download=True,
                                      transform=preprocessing)
    test_data = datasets.FashionMNIST(args.data, train=False, download=True,
                                     transform=preprocessing)
    permutation = torch.randperm(len(full_train), generator=torch.Generator().manual_seed(42))
    train_indices = permutation[:55000].tolist()
    valid_indices = permutation[55000:].tolist()
    if args.smoke:
        train_indices, valid_indices = train_indices[:512], valid_indices[:256]
        test_data = Subset(test_data, list(range(256)))
    train_data = Subset(full_train, train_indices)
    valid_data = Subset(full_train, valid_indices)
    options = {"batch_size": args.batch_size, "num_workers": 0,
               "pin_memory": device.type == "cuda"}
    train_loader = DataLoader(train_data, shuffle=True,
                              generator=torch.Generator().manual_seed(7), **options)
    valid_loader = DataLoader(valid_data, **options)
    test_loader = DataLoader(test_data, **options)
    model = FashionCNN().to(device)
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-4)
    scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
        optimizer, mode="min", factor=0.5, patience=1,
    )
    best = float("inf")
    stale = 0
    for epoch in range(args.epochs):
        train_loss, train_accuracy, _ = run_epoch(model, train_loader, device, optimizer)
        valid_loss, valid_accuracy, _ = run_epoch(model, valid_loader, device)
        if not torch.isfinite(torch.tensor(valid_loss)):
            raise RuntimeError("验证损失非有限")
        scheduler.step(valid_loss)
        print(f"epoch={epoch + 1} train={train_loss:.4f}/{train_accuracy:.3f} "
              f"valid={valid_loss:.4f}/{valid_accuracy:.3f}")
        if valid_loss < best:
            best, stale = valid_loss, 0
            torch.save({"model": model.state_dict(), "classes": full_train.classes,
                        "mean": [0.5], "std": [0.5], "epoch": epoch + 1,
                        "valid_loss": valid_loss}, best_path)
        else:
            stale += 1
        if stale >= 4:
            break

    checkpoint = torch.load(best_path, map_location="cpu", weights_only=True)
    restored = FashionCNN().to(device)
    restored.load_state_dict(checkpoint["model"])
    test_loss, test_accuracy, confusion = run_epoch(restored, test_loader, device)
    print(f"test_loss={test_loss:.4f} test_accuracy={test_accuracy:.3f}")
    print("混淆矩阵：行是真实类别，列是预测类别\n", confusion)
    recalls = confusion.diag().float() / confusion.sum(1).clamp_min(1)
    for name, recall in zip(checkpoint["classes"], recalls.tolist()):
        print(name, "recall", round(recall, 3))
    # 测试集上的一条展示，不重新选择模型或调整阈值。
    image, label = test_data[0]
    restored.eval()
    with torch.inference_mode():
        probability = restored(image.unsqueeze(0).to(device)).softmax(1)[0]
        confidence, predicted = probability.max(0)
    print("真实:", checkpoint["classes"][label],
          "预测:", checkpoint["classes"][predicted.item()],
          "分数:", round(confidence.item(), 3))

    main()

项目三：变长文本分类 ​

核心概念

把原始字符串转为可学习的整数序列，批内补齐长度，用有效位置掩码做池化。训练、保存、重载和线上推理必须共享同一套分词、词表、截断和标签定义。

任务、数据与模型取舍 ​

本项目仅依赖 Python 标准库与 PyTorch，使用内置英文短评做二分类，0 表示负面，1 表示正面。标签由句子含义指定，不是随机生成。训练、验证、测试是明确写出的不同句子，词表仅从训练句子建立。

这是几十条人工构造句子的管线教学，不是可靠情感分析基准。不同划分共享情感关键词是有意的教学简化；小测试集上的高分不能推断真实泛化。真实业务应收集足量标注数据，去重并按用户、来源或时间分组划分，检查领域、类别比例与标注一致性。

模型采用 Embedding→ 掩码平均池化 → 线性分类器。先用低成本基线验证管线，再替换为前文 GRU/Transformer。平均池化不区分词序，无法可靠理解否定、讽刺和转折。正则分词只用于英文演示，不能直接当作中文或多语言分词器。

完整脚本 ​

保存为 text_project.py，默认 CPU，无需下载数据，运行会创建输出目录并覆盖最佳检查点。预留 PAD=0、UNK=1；空字符串转换为一个 UNK，保证每个样本至少有一个有效位置。

python
import argparse
import re
from collections import Counter
from pathlib import Path
import torch
from torch import nn
from torch.nn.utils.rnn import pad_sequence
from torch.utils.data import Dataset, DataLoader

TRAIN = [
    ("a good movie", 1), ("a great film", 1),
    ("excellent acting", 1), ("i love this story", 1),
    ("a wonderful story", 1), ("the film is enjoyable", 1),
    ("good acting and great music", 1), ("i love the excellent music", 1),
    ("wonderful acting in this movie", 1), ("an enjoyable film with good music", 1),
    ("a bad movie", 0), ("a terrible film", 0),
    ("awful acting", 0), ("i hate this story", 0),
    ("a boring story", 0), ("the film is disappointing", 0),
    ("bad acting and terrible music", 0), ("i hate the awful music", 0),
    ("boring acting in this movie", 0), ("a disappointing film with bad music", 0),
]
VALID = [
    ("this movie is good", 1), ("the story is wonderful", 1),
    ("great acting in the film", 1), ("excellent enjoyable music", 1),
    ("this movie is bad", 0), ("the story is boring", 0),
    ("terrible acting in the film", 0), ("awful disappointing music", 0),
]
TEST = [
    ("a wonderful film with excellent acting", 1), ("i love this good music", 1),
    ("the movie is great and enjoyable", 1), ("good story and wonderful acting", 1),
    ("a boring film with awful acting", 0), ("i hate this bad music", 0),
    ("the movie is terrible and disappointing", 0), ("bad story and boring acting", 0),
]

def tokenize(text):
    return re.findall(r"[a-z]+(?:'[a-z]+)?", text.lower())

def build_vocab(rows):
    counts = Counter(token for text, _ in rows for token in tokenize(text))
    vocab = {"[PAD]": 0, "[UNK]": 1}
    for token in sorted(counts):
        vocab[token] = len(vocab)
    return vocab

def encode(text, vocab, max_length):
    tokens = tokenize(text)[:max_length]
    return torch.tensor([vocab.get(token, 1) for token in tokens] or [1], dtype=torch.long)

class ReviewDataset(Dataset):
    def __init__(self, rows, vocab, max_length):
        self.samples = [(encode(text, vocab, max_length), label) for text, label in rows]

    def __len__(self):
        return len(self.samples)

    def __getitem__(self, index):
        return self.samples[index]

def collate_reviews(batch):
    sequences, labels = zip(*batch)
    lengths = torch.tensor([len(sequence) for sequence in sequences])
    tokens = pad_sequence(sequences, batch_first=True, padding_value=0)
    return tokens, lengths, torch.tensor(labels, dtype=torch.long)

class TextClassifier(nn.Module):
    def __init__(self, vocab_size, embedding_dim):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embedding_dim, padding_idx=0)
        self.head = nn.Linear(embedding_dim, 2)

    def forward(self, tokens, lengths):
        embedded = self.embedding(tokens)
        positions = torch.arange(tokens.size(1), device=tokens.device)
        mask = positions.unsqueeze(0) < lengths.unsqueeze(1)
        summed = (embedded * mask.unsqueeze(-1)).sum(1)
        pooled = summed / lengths.clamp_min(1).unsqueeze(1)
        return self.head(pooled)

def run_epoch(model, loader, optimizer=None):
    training = optimizer is not None
    model.train(training)
    loss_sum = correct = count = 0
    with torch.set_grad_enabled(training):
        for tokens, lengths, labels in loader:
            if training:
                optimizer.zero_grad(set_to_none=True)
            logits = model(tokens, lengths)
            loss = nn.functional.cross_entropy(logits, labels)
            if training:
                loss.backward()
                nn.utils.clip_grad_norm_(model.parameters(), 1.0)
                optimizer.step()
            loss_sum += loss.detach().item() * len(labels)
            correct += (logits.argmax(1) == labels).sum().item()
            count += len(labels)
    if count == 0:
        raise ValueError("没有可评估的样本")
    return loss_sum / count, correct / count

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--epochs", type=int, default=60)
    parser.add_argument("--output", type=Path, default=Path("runs/text"))
    args = parser.parse_args()
    if args.epochs < 1:
        parser.error("epochs 必须大于 0")
    torch.manual_seed(42)
    args.output.mkdir(parents=True, exist_ok=True)
    best_path = args.output / "best.pt"
    # 阻止完全重复文本跨划分；真实项目还应检查近似重复与同源数据。
    text_sets = [{text for text, _ in rows} for rows in (TRAIN, VALID, TEST)]
    assert not (text_sets[0] & text_sets[1] or text_sets[0] & text_sets[2]
                or text_sets[1] & text_sets[2])
    vocab = build_vocab(TRAIN)
    config = {"embedding_dim": 24, "max_length": 64, "tokenizer": "english_regex_v1"}
    train_loader = DataLoader(
        ReviewDataset(TRAIN, vocab, config["max_length"]), batch_size=4, shuffle=True,
        collate_fn=collate_reviews, generator=torch.Generator().manual_seed(7),
    )
    valid_loader = DataLoader(ReviewDataset(VALID, vocab, config["max_length"]),
                              batch_size=8, collate_fn=collate_reviews)
    model = TextClassifier(len(vocab), config["embedding_dim"])
    optimizer = torch.optim.AdamW(model.parameters(), lr=0.02, weight_decay=1e-4)
    best_loss, stale = float("inf"), 0
    for epoch in range(args.epochs):
        train_loss, train_acc = run_epoch(model, train_loader, optimizer)
        valid_loss, valid_acc = run_epoch(model, valid_loader)
        if not torch.isfinite(torch.tensor(valid_loss)):
            raise RuntimeError("验证损失非有限")
        if valid_loss < best_loss:
            best_loss, stale = valid_loss, 0
            torch.save({"model": model.state_dict(), "vocab": vocab, "config": config,
                        "labels": ["negative", "positive"], "epoch": epoch + 1}, best_path)
        else:
            stale += 1
        if epoch == 0 or (epoch + 1) % 10 == 0:
            print(f"epoch={epoch + 1} train={train_loss:.4f}/{train_acc:.3f} "
                  f"valid={valid_loss:.4f}/{valid_acc:.3f}")
        if stale >= 10:
            break

    saved = torch.load(best_path, map_location="cpu", weights_only=True)
    cfg, vocabulary = saved["config"], saved["vocab"]
    if cfg["tokenizer"] != "english_regex_v1":
        raise ValueError("分词器版本不匹配")
    restored = TextClassifier(len(vocabulary), cfg["embedding_dim"])
    restored.load_state_dict(saved["model"])
    restored.eval()
    test_loader = DataLoader(ReviewDataset(TEST, vocabulary, cfg["max_length"]),
                             batch_size=8, collate_fn=collate_reviews)
    test_loss, test_acc = run_epoch(restored, test_loader)
    print(f"test_loss={test_loss:.4f} test_accuracy={test_acc:.3f} baseline=0.500")

    # UNK 随机初始化且这里没有训练到，遇到未知词不能假设模型理解其意义。
    queries = ["good enjoyable movie", "bad boring film", "spectacular cinematography", ""]
    with torch.inference_mode():
        for text in queries:
            sequence = encode(text, vocabulary, cfg["max_length"])
            lengths = torch.tensor([len(sequence)])
            logits = restored(sequence.unsqueeze(0), lengths)
            # 改变补齐长度不应改变同一句子的结果。
            padded = nn.functional.pad(sequence.unsqueeze(0), (0, 5), value=0)
            torch.testing.assert_close(logits, restored(padded, lengths))
            probabilities = logits.softmax(1)[0]
            confidence, predicted = probabilities.max(0)
            unknown_ratio = (sequence == 1).float().mean().item()
            print(repr(text), saved["labels"][predicted.item()],
                  "score", round(confidence.item(), 3), "unk_ratio", unknown_ratio)

if __name__ == "__main__":
    main()

梯度与更新检查示例 ​

下面代码独立在 CPU 上运行。零梯度与没有梯度不同：零梯度可能是当前样本的数学结果，没有梯度则可能是未参与计算、被冻结或已经断图。不能机械地要求所有参数每一步都有非零梯度。

python
import torch
from torch import nn

torch.manual_seed(7)
model = nn.Linear(2, 1)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
x = torch.randn(16, 2)
y = 2 * x[:, :1] - x[:, 1:2]
before = {name: value.detach().clone() for name, value in model.named_parameters()}
optimizer.zero_grad(set_to_none=True)
# 异常检测有明显开销，只应短时用于调试，并包含前向过程。
with torch.autograd.detect_anomaly():
    predicted = model(x)
    assert predicted.shape == y.shape
    loss = nn.functional.mse_loss(predicted, y)
    assert torch.isfinite(loss).item()
    loss.backward()
for name, parameter in model.named_parameters():
    assert parameter.grad is not None, name
    assert torch.isfinite(parameter.grad).all().item(), name
    print(name, "grad_norm", parameter.grad.norm().item())
optimizer.step()
for name, parameter in model.named_parameters():
    print(name, "max_update", (parameter.detach() - before[name]).abs().max().item())

如果极小样本能被拟合，而独立验证很差，重点转向数据分布、正则化和泛化；如果连极小样本都学不会，继续堆层数或换 Transformer 往往只会增加定位难度。

参数速查、自测与官方参考 ​

核心概念

学习目标不是记住某组“万能超参数”，而是能解释输入、目标、优化和评价之间的关系，并通过实验检验假设。

训练参数如何调整 ​

参数作用与常见起点验证方式
learning rate控制更新尺度；示例 AdamW 常从 1e-3 量级尝试，但非通用最优值先按数量级搜索，检查是否震荡、停滞或发散
batch size控制并行吞吐与梯度估计噪声在显存允许范围比较吞吐和验证曲线，不只看每步时间
epochs / patience限制训练预算、等待验证改善保存最佳验证模型；训练更久不保证更好
weight decay限制权重增长；与 optimizer 的实现有关与学习率共同验证，防止过强导致欠拟合
dropout训练时随机失活验证时 eval；小模型或小任务不一定需要
gradient clipping限制梯度范数AMP 中先 unscale；持续被裁剪时检查学习率和数据
num_workers并行准备数据从 0 定位问题，再测试 2、4 等；过多可能更慢
max_length控制文本截断与算力成本统计长度分布和截断率，而不是一律设最大值
seed便于对照实验报告多个种子的均值和波动；固定种子不保证跨平台逐位一致

分阶段实践路线 ​

  1. 基础闭环：运行张量和求导示例，手算一次梯度，独立写出线性回归训练循环，说明清梯度、反传和更新的顺序。
  2. 可靠评估：完成回归项目，替换为自己理解的表格数据，保存训练统计，和均值/线性基线比较。
  3. 模型结构：完成图像和文本项目，在同一划分上逐项替换 CNN、GRU、Transformer，不把模型变复杂当作成果。
  4. 训练工程：增加可信检查点恢复、结构化日志、多个种子和异常监测，验证重载预测一致性。
  5. 性能与规模：先用 profiler 找瓶颈，再试 AMP、数据加载优化、编译或 DDP；记录吞吐、内存与收敛差异。
  6. 部署交付：冻结预处理和模型版本，验证导出前后输出，对目标硬件测量延迟，并建立失败输入和漂移监控。

自测：能否不看代码回答

  • 为什么分类训练通常给交叉熵传 logits，而不是手动 softmax？
  • eval 与 no_grad 分别改变什么？冻结参数为什么不等于冻结 BatchNorm 统计？
  • 为什么标准化、词表和早停都不能依赖测试集？
  • 小批次不等长时，平均 loss 为什么不能简单平均每个 batch 的均值？
  • PAD 向量为零，为什么普通 mean 池化仍然不正确？
  • 梯度累积何时不等于真正的大 batch？混合精度如何影响裁剪时机？
  • DDP 为什么既需要梯度同步，也需要正确的数据分片与指标聚合？
  • “保存了权重”与“可以精确恢复训练”还差哪些状态？
