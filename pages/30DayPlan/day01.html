Day1 JS 核心：原型链、作用域、闭包、this 指向 ​

📖 基础知识讲解【基础原理 + 高级深挖知识点】 ​

基础原理 ​

1. 执行上下文与执行栈（作用域、闭包、this 的共同底座） ​

今天四个知识点其实是同一套运行机制的四个侧面，先建立这张底图，后面都好理解：

text
执行上下文 Execution Context
┌─────────────────────────────────────────────┐
│ 1. 词法环境 LexicalEnvironment               │
│      存 let / const / function 声明           │
│      ├─ 环境记录（变量本体存在这里）            │
│      └─ outer  →  指向「定义时」的外层环境      │ ← 作用域链 / 闭包
│ 2. 变量环境 VariableEnvironment               │
│      存 var 声明（函数作用域）                 │
│ 3. this 绑定 ThisBinding                     │ ← this 指向
└─────────────────────────────────────────────┘
侧面本质决定时机
作用域链环境记录上的 outer 指针链定义时（词法）
闭包函数持有的 outer 指针让外层环境不被回收定义时捕获环境
this上下文里的 ThisBinding 字段调用时（动态）

执行栈（调用栈）： 函数调用时压入新的执行上下文，返回时弹出。

js
function a() {
  b();
}
function b() {
  console.log("in b");
}
a();

// 执行栈变化：
// [全局] → [全局, a] → [全局, a, b] → [全局, a] → [全局]

✅ 一句话串起今天所有内容： 变量去哪找 → 看 outer（作用域链，定义时固定）；外层环境为什么没销毁 → 闭包还拿着 outer；this 是谁 → 看 ThisBinding，调用时才写入。

2. 作用域与作用域链 ​

  • JS 属于词法（静态）作用域：作用域关系在函数定义时确定，不是调用时决定。
  • 作用域分类： 全局作用域、函数作用域、let / const 带来的块级作用域。
  • 变量查找规则： 优先在当前作用域查找 → 一层层往外层作用域查找 → 直到全局作用域；未找到的标识符直接读取时抛出 ReferenceError。
声明方式变量提升与访问块级作用域是否挂载到 window
var声明提升，赋值前读取通常为 undefined没有浏览器经典脚本顶层声明通常成为 window 属性；函数内、ES Module 中不会
let / const存在暂时性死区（TDZ），声明初始化前不能访问有不会

提升优先级： 同一作用域内，函数声明整体提升且优先于 var 声明；重名时函数声明先生效，后续赋值再覆盖。

js
console.log(typeof fn); // 'function' 函数声明整体提升
console.log(a); // undefined  var 只提升声明
// console.log(b);       // ReferenceError：b 处于 TDZ
var a = 1;
let b = 2;
function fn() {}

⚠️ 容易混淆的边界：TDZ 不是"没提升"，而是"提升了但不许访问"

js
let x = "outer";
{
  // console.log(x);  // ❌ ReferenceError
  // 不是读到 'outer'！说明块级作用域里的 x 已经提升占位了，
  // 只是在初始化前处于 TDZ，访问直接报错
  let x = "inner";
}

✅ 验证"词法作用域 = 定义时决定"的经典对照：

js
var value = 1;

function foo() {
  console.log(value);
}

function bar() {
  var value = 2;
  foo(); // 调用发生在 bar 内部
}

bar(); // 1  ← 不是 2！
// foo 的 outer 在「定义时」就指向了全局环境，
// 跟它在哪里被调用完全无关。
// ❗ 对比记忆：作用域看定义位置，this 看调用位置。

3. 闭包 ​

定义： 函数与其捕获的外层词法环境的组合。外层函数执行完毕后，只要内层函数仍可达，它需要访问的外层变量就可以继续保留。

⚠️ 先说清最容易背错的一点：闭包捕获的是「变量本身」，不是「值的快照」

js
function outer() {
  let count = 0;
  return {
    inc: () => ++count,
    get: () => count,
  };
}
const o = outer();
o.inc();
o.inc();
console.log(o.get()); // 2
// inc 和 get 捕获的是同一个 count 变量（同一份环境记录），
// 不是各自拷贝了一份 0。

经典循环陷阱（var vs let，务必能解释清）：

js
// ❌ 全部输出 3：三个回调共享同一个函数作用域里的 i
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i)); // 3 3 3
}

// ✅ 输出 0 1 2：let 每轮迭代创建新的块级环境，各自捕获独立的 i
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i)); // 0 1 2
}

// ✅ ES5 时代的解法：用 IIFE 手动造一层作用域把当前值固定住
for (var j = 0; j < 3; j++) {
  (function (j) {
    setTimeout(() => console.log(j)); // 0 1 2
  })(j);
}

常用场景：

  • 私有化变量。
  • 函数柯里化。
  • 防抖、节流。
  • 保存回调上下文。
js
// 场景：私有变量，外部无法直接改 balance
function createAccount(init) {
  let balance = init; // 外部拿不到，只能走暴露的方法
  return {
    deposit(n) {
      if (n > 0) balance += n;
      return balance;
    },
    getBalance: () => balance,
  };
}
const acc = createAccount(100);
acc.deposit(50);
console.log(acc.getBalance()); // 150
console.log(acc.balance); // undefined  ← 真正做到了私有

4. JS 原型 & 原型链 ​

一句话先记住：JS 里每个对象都有一个隐藏的 __proto__（原型），指向它的构造函数的 prototype；原型本身也是对象，也有自己的 __proto__，一层一层往上找，这条链式查找路径就是原型链。

4.1 什么是原型 prototype ​
  • prototype：只有函数才有，是函数身上的一个属性，是一个对象。
  • 作用：用来存放实例公用的方法/属性，所有 new 出来的实例对象可以共享这份 prototype 上的东西，不用每个实例都复制一份，省内存。
js
function Person(name) {
  this.name = name;
}
// 写在构造函数 prototype 上，所有实例共用
Person.prototype.sayHi = function () {
  console.log("hi " + this.name);
};

const p1 = new Person("张三");
p1.sayHi(); // 实例自己没有 sayHi，去 Person.prototype 拿到
4.2 __proto__（隐式原型，实例身上才有） ​

每一个对象（实例）都有 __proto__

✅ 实例.__proto__ === 它的构造函数.prototype

js
p1.__proto__ === Person.prototype; // true

⚠️ 区分：

  • 函数：有 prototype（显式原型，给 new 出来的实例用）
  • 对象实例：有 __proto__（隐式原型，指向构造函数的 prototype）
4.3 什么是原型链 ​

当你访问一个对象的属性/方法：

  1. 先在对象自身身上找，找到了直接返回
  2. 找不到 → 就去 obj.__proto__（也就是构造函数 prototype）上面找
  3. 如果原型上还找不到 → 继续拿这个原型对象的 __proto__ 继续往上找
  4. 一直找到 Object.prototype.__proto__ = null，到头了，返回 undefined

这条一层一层向上查找的链条，就是原型链。

完整链条示例：

js
p1.__proto__; // Person.prototype
p1.__proto__.__proto__; // Object.prototype
p1.__proto__.__proto__.__proto__; // null 原型链终点
4.4 原型链核心特点（面试高频） ​
  1. 属性查找是向上查找，读取会顺着链找；赋值只会写在当前对象自身，不会修改原型上的属性
js
Person.prototype.age = 18;
p1.age = 20; // 直接给 p1 新增 age 属性，不会改原型上面的 age
console.log(p1.age); // 20 自身优先
console.log(Person.prototype.age); // 18 原型没变
  1. instanceof 的原理：沿着原型链，看右边构造函数的 prototype 是否出现在左边实例的整条原型链上
js
p1 instanceof Person; // true
p1 instanceof Object; // true
  1. 所有普通对象最终都继承自 Object.prototype，像 toString()、hasOwnProperty() 这些方法都来自这里
4.5 constructor：最容易被忽略的那条反向指针 ​

prototype 上天生带一个 constructor，指回构造函数本身，实例通过原型链也能读到它：

js
function Person() {}
Person.prototype.constructor === Person; // true
const p = new Person();
p.constructor === Person; // true  ← p 自身没有，顺着原型链读到的
p.hasOwnProperty("constructor"); // false

⚠️ 坑点：整体覆盖 prototype 会把 constructor 一起丢掉

js
// ❌ 直接赋新对象，constructor 指向错乱
Person.prototype = { sayHi() {} };
new Person().constructor === Object; // true  ← 变成了 Object！

// ✅ 两种正确做法
Person.prototype = {
  constructor: Person, // 手动补回
  sayHi() {},
};
// 或者只增量添加，不整体替换
Person.prototype.sayHi = function () {};

这也是后面「寄生组合继承」必须写 Child.prototype.constructor = Child 的原因。

4.6 原型链全景图（把函数也算进来） ​

只记「实例 → 构造函数.prototype」是不够的，函数本身也是对象，也有自己的原型链，面试常考 Function.__proto__ === Function.prototype：

text
       p1 (实例)
        │ __proto__
        ▼
  Person.prototype ──constructor──► Person (函数)
        │ __proto__                    │ __proto__
        ▼                              ▼
  Object.prototype         Function.prototype
        │ __proto__                    │ __proto__
        ▼                              ▼
      null                      Object.prototype ──► null

特殊记忆点：
  Function.__proto__ === Function.prototype   // true 自己指向自己
  Object.__proto__   === Function.prototype   // true Object 也是函数
  Function.prototype.__proto__ === Object.prototype  // true
js
// 口述时能说出这几条就够了
console.log(Person.__proto__ === Function.prototype); // true
console.log(Function.__proto__ === Function.prototype); // true
console.log(Object.prototype.__proto__); // null 原型链终点
4.7 手写极简版答案（面试口述直接说） ​

原型：JS 中每个构造函数都有 prototype 原型对象，用来存放实例共享的属性方法；每一个实例对象都有 __proto__ 隐式原型，指向构造函数的 prototype。

原型链：对象访问属性时，先在自身查找，找不到就顺着 __proto__ 一层一层向上查找，直到 Object.prototype.__proto__ 也就是 null 为止，这条查找链路就是原型链。

4.8 ❓ 高频追问顺带准备 ​
  • prototype 和 __proto__ 的区别？
  • hasOwnProperty 作用：只判断属性是不是对象自身的，不会去原型链上查找
  • 原型链继承怎么实现？优缺点？
js
// hasOwnProperty vs in：一个只看自身，一个会走原型链
const p2 = new Person("李四");
console.log("sayHi" in p2); // true   in 会沿原型链找
console.log(p2.hasOwnProperty("sayHi")); // false  不是自身属性
console.log(p2.hasOwnProperty("name")); // true   构造函数里挂的，是自身属性

// 遍历时的差异（易错点）
for (const k in p2) {
  // for...in 会遍历到原型上的可枚举属性
  if (Object.hasOwn(p2, k)) console.log("自身:", k);
}
console.log(Object.keys(p2)); // 只有自身可枚举属性

5. this 绑定四大基础形式 ​

  1. 普通函数调用：默认绑定。
  2. 对象方法调用：隐式绑定。
  3. new 调用：构造绑定。
  4. call / apply / bind：显式指定绑定，bind 返回绑定后的函数。
js
"use strict";

function show() {
  return this;
}

// 1. 默认绑定：严格模式为 undefined，非严格模式为全局对象
console.log(show()); // undefined

// 2. 隐式绑定：this 指向调用它的那个对象（点号左边）
const user = {
  name: "Tom",
  getName() {
    return this.name;
  },
  child: {
    name: "Jerry",
    getName() {
      return this.name;
    },
  },
};
console.log(user.getName()); // 'Tom'
console.log(user.child.getName()); // 'Jerry'，只看最近一层调用者

// 3. 构造绑定：this 指向新创建的实例
function Person(name) {
  this.name = name;
}
console.log(new Person("Jack").name); // 'Jack'

// 4. 显式绑定：手动指定 this
function greet(greeting, mark) {
  return `${greeting}, ${this.name}${mark}`;
}
console.log(greet.call(user, "hi", "!")); // 'hi, Tom!' 参数逐个传
console.log(greet.apply(user, ["hello", "?"])); // 'hello, Tom?' 参数用数组传
const boundGreet = greet.bind(user, "hey"); // bind 返回新函数，可预传参数
console.log(boundGreet("~")); // 'hey, Tom~'

典型 this 丢失场景： 方法被赋值给变量单独调用、作为 setTimeout / 数组方法的回调传入、解构出对象方法后调用——这些都会退回默认绑定。

js
const obj = {
  name: "obj",
  getName() {
    return this.name;
  },
};
const fn = obj.getName;
console.log(obj.getName()); // 'obj' 隐式绑定
console.log(fn()); // 严格模式下 TypeError；非严格模式读到全局
setTimeout(obj.getName, 0); // 同样丢失，需 bind 或箭头函数包一层

第 5 类：DOM 事件绑定（实际开发最常遇到）

js
btn.addEventListener("click", function () {
  console.log(this); // 指向绑定事件的 DOM 元素（btn）
});

btn.addEventListener("click", () => {
  console.log(this); // ❌ 不是 btn，是外层词法环境的 this
});
// 📌 需要拿 currentTarget 时用普通函数；
//    需要拿组件实例时用箭头函数，别记反。

class 里的 this：方法默认不绑定实例

js
class Counter {
  count = 0;

  // 普通方法：挂在 prototype 上，this 看调用方式
  inc() {
    this.count++;
  }

  // 类字段 + 箭头函数：挂在实例上，this 永远是实例
  incArrow = () => {
    this.count++;
  };
}

const c = new Counter();
const { inc, incArrow } = c; // 解构后丢失调用者
// inc();        // ❌ TypeError：class 内部是严格模式，this 为 undefined
incArrow(); // ✅ 正常，this 已在创建实例时固定
c.inc(); // ✅ 正常，点号调用

⚠️ 代价对比： 箭头函数类字段每个实例都复制一份函数，不共享原型、无法被子类重写覆盖；普通方法省内存可继承但需要手动 bind。React 类组件里 this.handleClick = this.handleClick.bind(this) 解决的就是这个问题。

✨ 高级深挖知识点 ​

1. this 绑定优先级 ​

面试中通常按以下顺序理解普通函数的绑定规则：

text
new 绑定 > bind 硬绑定 > call / apply 显式绑定
         > 对象隐式绑定 > 普通函数默认绑定

关键点：

  • bind 硬绑定后，call / apply 无法修改已绑定的 this。
  • 如果原函数可构造，使用 new 调用 bind 返回的函数时，会忽略绑定的 this，但仍保留预传参数。
  • 普通函数默认调用时，严格模式下 this 是 undefined；非严格模式下一般是全局对象。
  • 箭头函数不参与上述动态绑定规则。
js
function Tag(label) {
  this.label = label;
  this.who = this.name; // 构造绑定时 this.name 为 undefined
}

const a = { name: "A", Tag };
const b = { name: "B" };

// 隐式 > 默认：点号左边的 a 胜出
console.log(a.Tag("t1"), a.label, a.who); // undefined 't1' 'A'

// 显式 > 隐式：call 指定的 b 覆盖隐式的 a
a.Tag.call(b, "t2");
console.log(b.label, b.who); // 't2' 'B'

// 硬绑定 > 显式：bind 之后 call / apply 改不动
const bound = Tag.bind(a, "fixed");
bound.call(b);
console.log(a.label, a.who); // 'fixed' 'A'，b 未被写入

// new > 硬绑定：忽略绑定的 a，但保留预传参数 'fixed'
const ins = new bound();
console.log(ins.label, ins.who, ins instanceof Tag); // 'fixed' undefined true

// 箭头函数不参与：call 无效，this 来自定义时的外层词法环境
const arrow = () => this;
console.log(arrow.call(a) === arrow()); // true

2. 寄生组合继承 ​

  • 组合继承的缺陷： 典型实现中，设置子类原型时执行一次父构造函数，创建子类实例时又执行一次。
  • 寄生组合继承： 使用 Object.create(父类.prototype) 建立原型关系，仅在创建实例时调用父构造函数。
  • 与 ES6 class 的关系： 实例原型链结构类似，但不能把 class extends 完全等同于寄生组合继承；它还建立构造函数之间的继承，并有 super、类构造器等专门语义。

✅ 用代码看清"父构造函数被调用两次"到底坏在哪：

js
function Parent(name) {
  this.name = name;
  this.list = []; // 引用类型放在实例上
  console.log("Parent 执行");
}

// ❌ 组合继承
function Child1(name) {
  Parent.call(this, name); // 第 2 次
}
Child1.prototype = new Parent(); // 第 1 次（多余）
Child1.prototype.constructor = Child1;
new Child1("a");
// 输出：Parent 执行 ×2
// 且 Child1.prototype 上残留了一份无用的 name / list 属性，
// 被实例同名属性屏蔽，纯属浪费内存。

// ✅ 寄生组合继承
function Child2(name) {
  Parent.call(this, name); // 只有这一次
}
Child2.prototype = Object.create(Parent.prototype); // 只借原型，不执行构造
Child2.prototype.constructor = Child2;
new Child2("b");
// 输出：Parent 执行 ×1，原型上也没有多余属性

方式父构造调用次数引用类型共享问题能否传参
原型链继承1❌ 所有实例共享❌
借用构造函数1✅ 无✅
组合继承2✅ 无（但原型有冗余）✅

3. 属性屏蔽（shadowing）：赋值为什么"写不进原型" ​

obj.x = v 不是简单写值，引擎会先沿原型链查找 x，结果分三种：

js
const proto = {
  a: 1,
  get b() {
    return 2;
  }, // 只有 getter，没有 setter
  set c(v) {
    this._c = v;
  }, // 有 setter
};
const obj = Object.create(proto);

// 情况 1：原型上是普通数据属性 → 在自身新建同名属性，屏蔽原型
obj.a = 10;
console.log(obj.a, proto.a); // 10 1  ✅ 原型没被改

// 情况 2：原型上是只有 getter 的访问器 → 赋值被忽略
obj.b = 20;
console.log(obj.b); // 2  严格模式下直接 TypeError

// 情况 3：原型上有 setter → 调用 setter，不会新建自身属性
obj.c = 30;
console.log(obj.hasOwnProperty("c"), obj._c); // false 30

⚠️ 还有一种容易忽略的：原型上的数据属性若 writable: false，非严格模式下赋值静默失败，严格模式抛错。

📌 结论： "读取走原型链、赋值只写自身"只是默认情况，遇到访问器属性和只读属性要单独判断。

4. 闭包与内存泄漏 ​

闭包本身不是泄漏。当不再需要的闭包仍被定时器、事件监听或全局容器引用时，它捕获的对象可能无法释放。

典型场景： 组件定时器、事件监听没有清除，闭包一直持有 DOM 引用，已移除的 DOM 仍然可达。

排查工具与流程：

  1. 使用 Chrome DevTools 的 Memory 面板拍摄堆快照。
  2. 反复执行组件挂载、卸载，再比较快照。
  3. 查找 Detached DOM（游离 DOM）节点。
  4. 追溯引用链，定位定时器、监听器或闭包持有者。
  5. 清理后再次验证；游离节点不一定都是泄漏，需要结合生命周期判断。

✅ 正反对照：同一段代码泄漏与不泄漏的差别只在"有没有清理"

js
// ❌ 泄漏：定时器一直可达 → 闭包不释放 → bigData、el 都回收不了
function mount() {
  const el = document.getElementById("box");
  const bigData = new Array(1e6).fill("x");
  setInterval(() => {
    el.textContent = bigData.length; // 闭包持有 el + bigData
  }, 1000);
}
// 即使之后 el 被 removeChild，它仍被闭包引用 → Detached DOM

// ✅ 正确：返回清理函数，卸载时断开引用链
function mount() {
  const el = document.getElementById("box");
  let bigData = new Array(1e6).fill("x");
  const timer = setInterval(() => {
    el.textContent = bigData.length;
  }, 1000);

  return function unmount() {
    clearInterval(timer); // 断开 GC Root 到闭包的引用
    bigData = null; // 可选：主动释放大对象
  };
}

📌 判断标准： 闭包会不会泄漏，看的不是"用没用闭包"，而是有没有一条从 GC Root（定时器队列、事件监听表、全局变量）出发指向它的引用链。

5. 箭头函数特性 ​

  • 没有自己的 this 和 arguments；使用时从外层词法环境获取。
  • 没有用于构造实例的 prototype，不能作为 new 的构造函数。
  • this 在创建函数时捕获外层 this，call / apply / bind 无法重新指定它。
  • 对象字面量不产生新的 this 绑定，因此箭头方法的 this 不会自动指向该对象。

除了 this，这几条也常被追问：

js
const arrow = () => {};
console.log(arrow.prototype); // undefined  → 不能 new
// new arrow();                  // ❌ TypeError: arrow is not a constructor

// 没有自己的 arguments，拿到的是外层函数的
function outer() {
  const inner = () => arguments[0];
  return inner("inner-arg");
}
console.log(outer("outer-arg")); // 'outer-arg'  ← 不是 'inner-arg'
// ✅ 箭头函数要收参数只能用剩余参数
const inner2 = (...args) => args;

// 也没有 super 和 new.target

❓ 高频面试题【基础简答 + 连环追问链 + 精简口述答案 + 项目关联话术】 ​

题 1：什么是闭包？使用场景和缺点是什么？ ​

精简口述答案：

闭包是函数与其捕获的外层词法环境的组合。外层函数执行完，内层函数依旧可以读取外层变量。场景包括私有变量、柯里化、防抖和节流。它会延长被捕获变量的生命周期，不合理保留引用可能导致内存泄漏，应及时清理不再需要的订阅和引用。

连环追问链：

  1. 追问：闭包内存泄漏如何排查定位？
    • 答：使用 Chrome Memory 堆快照，查找游离 DOM 节点并追溯引用来源；页面销毁时清除定时器、解绑事件，必要时置空长期持有的引用。
  2. 追问：写一段柯里化示例，柯里化的好处是什么？
    • 答：把多参函数转换为逐次接收参数的函数，例如 const add = a => b => a + b，调用 add(1)(2) 得到 3；可以复用参数，并在参数收集完成后执行计算。

✅ 项目关联话术（按真实经历替换）：

我在后台管理项目封装防抖函数，依靠闭包保存定时器 ID，搜索输入高频触发时减少接口请求；初期踩坑页面切换没有清除定时器，造成内存持续上涨，在组件销毁钩子清除定时器解决。

题 2：prototype 和 __proto__ 的区别是什么？原型链如何查找？ ​

精简口述答案：

普通构造函数的 prototype 存放实例共享的属性和方法；对象的内部原型串联原型链，通常可以通过 __proto__ 访问，更推荐使用 Object.getPrototypeOf()。访问属性时优先读取自身，找不到就沿原型链向上查找，直到 null。

连环追问链：

  1. 追问：Object.create(null) 生成的对象有原型吗？
    • 答：它的内部原型为 null，不会继承 Object.prototype 上的 toString 等方法，适合纯净字典对象。注意其 obj.__proto__ 默认是 undefined，不是 null，应通过 Object.getPrototypeOf(obj) 验证。
  2. 追问：ES6 class 继承的原型关系是什么？
    • 答：对普通的 class Child extends Parent，Object.getPrototypeOf(Child) === Parent，且 Object.getPrototypeOf(Child.prototype) === Parent.prototype，分别建立静态成员和实例方法的继承链。

✅ 项目关联话术（按真实经历替换）：

项目封装工具类，公共方法挂载到构造函数 prototype，所有实例共用同一份函数，减少内存占用，避免每个实例重复创建函数。

题 3：this 绑定有哪几种？优先级是什么？箭头函数有什么特点？ ​

精简口述答案：

常见绑定方式包括 new、bind、call / apply、对象方法调用和默认调用。可以按构造绑定、硬绑定、显式绑定、隐式绑定、默认绑定理解优先关系。箭头函数没有独立的 this，捕获外层 this，call / bind 无法修改，也不能通过 new 实例化。

连环追问链：

  1. 追问：bind 绑定之后，call 还能修改 this 吗？
    • 答：不能，call / apply 无法覆盖硬绑定；但原函数可构造时，new 调用绑定函数会使用新实例，而非绑定对象。
  2. 追问：对象字面量里使用箭头函数作为方法有什么坑？
    • 答：箭头函数捕获外层 this，不会指向对象自身。浏览器经典脚本顶层通常为 window，ES Module 顶层则是 undefined；也可能捕获包围它的函数的 this，不能一概认定是 window。

✅ 项目关联话术（按真实经历替换）：

业务开发回调经常丢失 this，早期用 const that = this 保存实例，现在直接使用箭头函数捕获外层组件上下文，简化代码。

function myNew(Ctor, ...args) {

  const ret = Ctor.apply(obj, args);

题 3：手写 bind，支持 new 场景 ​

核心实现（面试可默写版）：

js
Function.prototype.myBind = function (context, ...args1) {
  if (typeof this !== "function") {
    throw new TypeError("myBind must be called on a function");
  }
  const fn = this;
  const boundFn = function (...args2) {
    // new.target 判断是否为 new 调用
    const ctx = new.target ? this : context;
    return fn.apply(ctx, [...args1, ...args2]);
  };
  // 箭头函数、class 方法等没有 prototype，需先判空
  if (fn.prototype) {
    boundFn.prototype = Object.create(fn.prototype);
  }
  return boundFn;
};

✅ 边界 Case 自测： 普通调用时绑定 this 生效；new 调用时忽略绑定的 this；支持预传参数；传入箭头函数时不抛错。

此代码只演示普通可构造函数，不是原生 bind 的完整实现：class 构造器不能通过 apply 调用；原生绑定函数不暴露自己的 prototype，name、length 也与此实现不同。仅在练习环境扩展 Function.prototype。

🔁 变种拓展题： 顺手手写 myCall，用临时 Symbol 属性避免污染目标对象。

js
Function.prototype.myCall = function (context, ...args) {
  // const ctx = context === undefined || context === null ? window : context;
  const ctx =
    context === null || context === undefined ? globalThis : Object(context);
  const key = Symbol("fn");
  ctx[key] = this;
  try {
    return ctx[key](...args);
  } finally {
    delete ctx[key];
  }
};

题 4：手写 instanceof 与 Object.create ​

核心实现：

js
// 沿着原型链逐级比对，直到 null
function myInstanceof(left, right) {
  if (typeof right !== "function") {
    throw new TypeError("Right-hand side must be callable");
  }
  // 原始值不在原型链讨论范围内，直接 false
  if (left === null || (typeof left !== "object" && typeof left !== "function")) {
    return false;
  }
  let proto = Object.getPrototypeOf(left);
  const prototype = right.prototype;
  while (proto !== null) {
    if (proto === prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}

// 只做原型关联，不执行构造函数
function myObjectCreate(proto, propsDesc) {
  if (typeof proto !== "object" && typeof proto !== "function") {
    throw new TypeError("proto must be an Object or null");
  }
  function F() {}
  F.prototype = proto;
  const obj = new F();
  if (propsDesc) Object.defineProperties(obj, propsDesc);
  return obj;
}

✅ 边界 Case 自测： myInstanceof(1, Number) 为 false（原始值）；myInstanceof([], Object) 为 true；右侧非函数时抛错；myObjectCreate(null) 得到无原型对象（注意这种 F.prototype = null 的降级实现拿不到真正 [[Prototype]] = null，纯净字典仍应用原生 Object.create(null)）。

🔁 变种拓展题： 说明 instanceof 的两个失效场景——跨 iframe / 跨 Realm 时构造函数不同一，以及 Symbol.hasInstance 可被自定义覆盖。

js
class Even {
  static [Symbol.hasInstance](n) {
    return typeof n === "number" && n % 2 === 0;
  }
}
console.log(2 instanceof Even); // true  ← 已不是原型链判断
// 📌 类型判断更稳的方案：Object.prototype.toString.call(x)

题 5：函数柯里化（闭包经典应用） ​

核心实现：

js
function curry(fn) {
  return function curried(...args) {
    // 参数够了就执行
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    // 不够则继续收集
    return function (...rest) {
      return curried.apply(this, [...args, ...rest]);
    };
  };
}

const sum = curry((a, b, c) => a + b + c);
console.log(sum(1)(2)(3)); // 6
console.log(sum(1, 2)(3)); // 6
console.log(sum(1)(2, 3)); // 6

✅ 边界 Case 自测： 一次性传满参数可直接执行；分多次任意组合传参结果一致；原函数使用剩余参数或默认参数时 fn.length 不准，需显式传入期望参数个数。

🔁 变种拓展题： 实现 add(1)(2)(3) 这种参数个数不固定、最终靠隐式转换取值的写法。

js
function add(...args) {
  const fn = (...rest) => add(...args, ...rest);
  // 参与运算 / 字符串拼接时触发求和
  fn[Symbol.toPrimitive] = () => args.reduce((a, b) => a + b, 0);
  return fn;
}
console.log(+add(1)(2)(3)); // 6
console.log(`${add(1, 2)(3)(4)}`); // '10'

题 6：防抖与节流（闭包 + this 综合） ​

核心实现：

js
// 防抖：停止触发 delay 后才执行；immediate 控制是否首次立即执行
function debounce(fn, delay = 300, immediate = false) {
  let timer = null;
  return function (...args) {
    if (timer) clearTimeout(timer);
    if (immediate && !timer) {
      fn.apply(this, args); // 用 apply 把 this 传回原调用者
    }
    timer = setTimeout(() => {
      timer = null;
      if (!immediate) fn.apply(this, args);
    }, delay);
  };
}

// 节流：时间戳版，固定间隔最多执行一次
function throttle(fn, interval = 300) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);
    }
  };
}

✅ 边界 Case 自测： this 与事件对象 args 必须正确透传（不能用箭头函数包装返回的函数体外层）；连续触发只执行一次；提供取消能力以便组件卸载时清理。

js
debounced.cancel = function () {
  clearTimeout(timer);
  timer = null;
};

🔁 变种拓展题： 对比两种节流实现的差异——时间戳版首次立即执行、停止触发后不再补最后一次；定时器版首次延迟执行、会保留最后一次触发。要求首尾都执行时需两者结合。

常见坑解决方案
❌ 对象字面量方法使用箭头函数，this 不指向对象自身，读取不到对象属性✅ 需要动态接收者的方法使用普通函数或方法简写
❌ 闭包定时器忘记清除，组件反复挂载后定时器持续执行，可能持续持有对象✅ 组件销毁时执行 clearTimeout；周期任务用 clearInterval，并解绑相关事件监听
❌ 在业务运行过程中直接修改 __proto__，造成原型变化并可能影响性能✅ 优先在创建时使用 Object.create；确有必要才使用 Object.setPrototypeOf，它同样可能影响性能
❌ 把对象方法当回调直接传给 setTimeout / 数组方法，this 退回默认绑定✅ 用 bind 或箭头函数包一层，保留原始接收者
❌ 替换子类 prototype 后忘记修正 constructor，实例 constructor 指向父类✅ 紧跟一行 Child.prototype.constructor = Child
❌ for (var i) 循环里注册回调，回调全部读到循环结束后的同一个 i✅ 改用 let 形成每轮独立的块级环境，或用 IIFE 固定当前值
❌ 把引用类型（数组 / 对象）直接挂在 prototype 上，一个实例修改影响全部实例✅ 引用类型在构造函数里用 this.list = [] 初始化，prototype 只放方法
❌ 解构对象方法（const { fn } = obj）后调用，this 丢失✅ 解构前先 bind，或在 class 中用箭头函数类字段定义
❌ 防抖 / 节流返回的函数写成箭头函数，拿不到事件触发元素的 this✅ 返回普通函数并内部用 fn.apply(this, args) 透传上下文和参数
❌ 用 obj.x = v 试图改原型上的访问器属性，赋值静默失效✅ 原型上只有 getter 时赋值无效（严格模式报错），需改设计或通过 Object.defineProperty 处理
