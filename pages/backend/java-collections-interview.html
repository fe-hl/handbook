一、数组与 List 篇 ​

1.1 数组的随机查询为什么这么快？ ​

核心原理

数组的元素槽位连续排列，按下标访问可以直接计算偏移，时间复杂度为 O(1)，不需要逐个遍历。

寻址公式：元素地址 = baseAddress + i * dataTypeSize。

  • baseAddress：首个元素的地址。
  • dataTypeSize：每个元素槽位的大小，Java 的 int 占 4 个字节。
  • i：下标。

假设首个元素地址是 10，存 int，array[1] 的地址就是 10 + 1 * 4 = 14。一次计算就能定位，不管数组多长，按下标访问的复杂度都一样。

text
栈帧中的引用                  堆中的数组元素区（示意）
┌──────────────┐        ┌──────┬──────┬──────┬──────┬──────┬──────┐
│  array 引用  │ ─────► │  22  │  33  │  88  │  66  │  55  │  25  │
└──────────────┘        ├──────┼──────┼──────┼──────┼──────┼──────┤
                       │  10  │  14  │  18  │  22  │  26  │  30  │
                       │ [0]  │ [1]  │ [2]  │ [3]  │ [4]  │ [5]  │
                       └──────┴──▲───┴──────┴──────┴──────┴──────┘
                                 │
                       10 + 1 × 4 = 14，直接定位 array[1]

连续的是元素槽位，不一定是对象本身

这里省略了 JVM 数组对象头、对齐等细节，地址仅为教学示意。引用数组连续存放的是对象引用，被引用的对象不要求连续；ArrayList 的底层 Object 数组同样如此。数组引用也不一定存在栈上，它还可能是对象字段。

1.2 数组插入、删除为什么慢？ ​

Java 数组的长度固定，本身没有增删方法。这里的“插入、删除”指在数组上维护一个紧凑的逻辑序列，例如 ArrayList。

  • 插入第 k 个位置：把 k 到末尾的元素向后移动，给新元素腾出位置。
  • 删除第 k 个位置：把后面的元素向前移动，维持元素的逻辑顺序。
  • 最好情况是操作末尾，不需要移动其他元素；最坏情况是操作头部，要移动几乎全部元素；平均移动约一半，复杂度为 O(n)。

慢的是维护序列，而不是内存会出现空洞

把数组中的某个元素设为 null，不会破坏数组内存的连续性，也不需要移动元素。ArrayList 搬移元素，是为了维持 [0, size) 内的紧凑序列。尾部追加不扩容时是 O(1)，需要扩容时是 O(n)，均摊为 O(1)。

1.3 无序数组和有序数组的查找效率一样吗？ ​

按下标访问都为 O(1)；区别在于“按值查找”：无序数组一般逐个比对，复杂度 O(n)；有序数组可以使用二分查找，每次排除一半，复杂度 O(log n)。

1.4 ArrayList 底层是如何实现的？ ​

  • 底层数据结构：动态数组，实际存储在 Object 数组中。
  • 初始容量：JDK 8 无参构造先使用空数组，第一次普通 add 才分配默认容量 10。
  • 扩容逻辑：通常扩到原容量的 1.5 倍；不够则取所需容量，每次扩容都要拷贝数组。
  • add 方法流程：确保 size + 1 放得下 → 容量不足则 grow → 将元素放到 size 位置并递增 size → 返回 true。

简化后的 JDK 8 源码（省略部分校验、modCount 等细节）：

java
public class ArrayList<E> {
    private static final int DEFAULT_CAPACITY = 10;
    // 两个不同的空数组，用于区分无参构造与容量为 0 的构造
    private static final Object[] DEFAULTCAPACITY_EMPTY_ELEMENTDATA = {};
    private static final Object[] EMPTY_ELEMENTDATA = {};
    private static final int MAX_ARRAY_SIZE = Integer.MAX_VALUE - 8;
    transient Object[] elementData;
    private int size;

    public ArrayList() {
        this.elementData = DEFAULTCAPACITY_EMPTY_ELEMENTDATA;
    }

    public ArrayList(int initialCapacity) {
        if (initialCapacity > 0) {
            this.elementData = new Object[initialCapacity];
        } else if (initialCapacity == 0) {
            this.elementData = EMPTY_ELEMENTDATA;
        } else {
            throw new IllegalArgumentException("Illegal Capacity: " + initialCapacity);
        }
    }

    public boolean add(E e) {
        ensureCapacityInternal(size + 1);
        elementData[size++] = e;
        return true;
    }

    private void ensureCapacityInternal(int minCapacity) {
        ensureExplicitCapacity(calculateCapacity(elementData, minCapacity));
    }

    private static int calculateCapacity(Object[] elementData, int minCapacity) {
        if (elementData == DEFAULTCAPACITY_EMPTY_ELEMENTDATA) {
            return Math.max(DEFAULT_CAPACITY, minCapacity);
        }
        return minCapacity;
    }

    private void ensureExplicitCapacity(int minCapacity) {
        if (minCapacity - elementData.length > 0) {
            grow(minCapacity);
        }
    }

    private void grow(int minCapacity) {
        int oldCapacity = elementData.length;
        int newCapacity = oldCapacity + (oldCapacity >> 1);
        if (newCapacity - minCapacity < 0) {
            newCapacity = minCapacity;
        }
        if (newCapacity - MAX_ARRAY_SIZE > 0) {
            newCapacity = hugeCapacity(minCapacity);
        }
        elementData = java.util.Arrays.copyOf(elementData, newCapacity);
    }

    private static int hugeCapacity(int minCapacity) {
        if (minCapacity < 0) {
            throw new OutOfMemoryError();
        }
        return minCapacity > MAX_ARRAY_SIZE ? Integer.MAX_VALUE : MAX_ARRAY_SIZE;
    }
}

关键点：oldCapacity + (oldCapacity >> 1) 是 old + old / 2，整数运算会向下取整；Arrays.copyOf 内部调用 System.arraycopy，扩容复制的开销是 O(n)。

1.5 ArrayList list = new ArrayList(10) 中的 list 扩容几次？ ​

一次都没有扩容。 这条语句通过带参构造直接分配容量为 10 的数组，没有插入元素，size 仍为 0。它属于初始化，不是从旧数组扩容。

java
ArrayList<String> list = new ArrayList<>(10);
System.out.println(list.size()); // 0，容量不是元素个数
for (int i = 0; i < 10; i++) {
    list.add("item" + i);       // 放入前 10 个元素，不扩容
}
list.add("item10");            // 第 11 个元素触发扩容：10 → 15

指定容量不等于以后不会扩容

无参构造第一次 add 通常分配 10；指定容量为 0 时第一次 add 只需分配 1。已知数据规模时可提前指定合理容量，减少后续复制。

1.6 如何实现数组和 List 之间的转换？ ​

数组转 List：Arrays.asList ​

java
String[] array = {"a", "b", "c"};
List<String> list = Arrays.asList(array);
array[0] = "x";
System.out.println(list.get(0)); // x：共享原数组
list.set(1, "y");
System.out.println(array[1]);   // y：修改也会影响原数组

追问：修改数组内容，List 受影响吗？ 受影响。返回的是 Arrays 的内部类 ArrayList，而不是 java.util.ArrayList；它只包装传入数组，不做拷贝。

简化后的 JDK 实现：

java
package java.util;

public class Arrays {
    public static <T> List<T> asList(T... a) {
        return new ArrayList<>(a);
    }

    private static class ArrayList<E> extends AbstractList<E>
            implements RandomAccess, java.io.Serializable {
        private static final long serialVersionUID = -2764017481108945198L;
        private final E[] a;

        ArrayList(E[] array) {
            a = Objects.requireNonNull(array);
        }

        @Override
        public int size() {
            return a.length;
        }

        @Override
        public E get(int index) {
            return a[index];
        }

        @Override
        public E set(int index, E element) {
            E oldVal = a[index];
            a[index] = element;
            return oldVal;
        }
        // 未实现改变长度的 add/remove，相关调用会抛异常
    }
}

固定长度不等于不可修改

得到的 List 支持 set，但不支持改变长度的增删操作。传入 int 数组时不会自动拆成整数列表，而是得到只有一个数组元素的 List。

java
// 错误：固定长度列表不能追加
List<String> fixed = Arrays.asList("a", "b");
// fixed.add("c"); // UnsupportedOperationException

// 正确：需要增删时，复制到真正的 ArrayList
List<String> mutable = new ArrayList<>(fixed);
mutable.add("c");

int[] numbers = {1, 2, 3};
List<int[]> oneElement = Arrays.asList(numbers);
System.out.println(oneElement.size()); // 1，不是 3

List 转数组：toArray ​

无参 toArray 返回 Object 数组；传入指定类型的数组，返回对应类型的数组。

java
ArrayList<String> list = new ArrayList<>();
list.add("a");
Object[] objArr = list.toArray(); // 不能强转为 String[]
String[] strArr = list.toArray(new String[0]);
list.set(0, "b");
System.out.println(strArr[0]);   // a：数组槽位是独立的

无参 toArray 的 JDK 实现：

java
public Object[] toArray() {
    return Arrays.copyOf(elementData, size);
}

拷贝的是数组，不是每个对象

改变 List 的大小、替换某个元素，不会改变返回数组的槽位。但引用元素仍指向同一个对象，修改对象内部字段时，两边都能看到变化，这是浅拷贝。带参 toArray 在传入数组足够大时会复用它，而不是必然创建新数组。

java
List<StringBuilder> list = new ArrayList<>();
list.add(new StringBuilder("a"));
StringBuilder[] array = list.toArray(new StringBuilder[0]);
list.get(0).append("b");
System.out.println(array[0]); // ab：两边共享同一个元素对象

1.7 ArrayList 和 LinkedList 的区别是什么？ ​

比较项ArrayListLinkedList
底层结构动态数组双向链表
按下标访问O(1)支持 get(index)，但需要遍历，O(n)
按值查找通常 O(n)通常 O(n)
尾部追加均摊 O(1)，扩容时 O(n)O(1)
头部插入、删除O(n)，移动元素O(1)，调整指针
中间插入、删除O(n)，移动元素按索引定位 O(n)，已定位节点后改指针 O(1)
内存与局部性数组容量可能有空余，通常局部性更好每个节点额外存前后引用和对象头
线程安全不安全不安全

不要说 LinkedList 不支持下标查询

它支持 List 的下标接口，只是不具备快速随机访问能力。也不能笼统说“链表增删一定更快”：若先按下标寻找中间节点，遍历本身就是 O(n)。只有已定位节点，或直接操作头尾时，指针修改才是 O(1)。

1.8 项目中如何解决 ArrayList / LinkedList 的线程安全问题？ ​

方案一：集合保持线程封闭。 方法内新建集合且不向其他线程共享，通常不需要同步。局部引用位于栈帧并不意味着堆中的集合天然隔离，关键是对象有没有被其他线程访问。

方案二：共享时选择合适的并发容器或加锁。

  • List 语义：使用 Collections.synchronizedList；每个方法同步，但遍历和复合操作需要对同一个包装列表加锁。
  • 读多写少：使用 CopyOnWriteArrayList，写时复制，迭代器使用快照，不保证看到后续修改，写入成本较大。
  • 队列语义：使用 ConcurrentLinkedQueue 或 BlockingQueue 的具体实现。前者不支持下标、不能存 null，不是 List 的等价替换。
java
List<String> list = Collections.synchronizedList(new ArrayList<>());
list.add("a");
synchronized (list) {
    for (String item : list) {
        System.out.println(item);
    }
    // contains + add 也是复合操作，必须一起保护
    if (!list.contains("b")) {
        list.add("b");
    }
}

方法安全不代表操作组合安全

只给单次方法加锁，不能让“先判断后添加”自动成为原子操作。不加锁遍历可能抛 ConcurrentModificationException，也可能出现其他不一致行为；fail-fast 只是尽力检测，不能作为线程安全保证。共享的元素对象若可变，也需要单独考虑同步。

Vector 与 synchronizedList 主要是整体锁方案。JDK 7 的 ConcurrentHashMap 使用 Segment 分段锁；JDK 8 主要使用 CAS 与桶级 synchronized，不能把所有版本都概括成“分段锁”。

二、HashMap 原理篇 ​

2.1 说一下 HashMap 的实现原理？ ​

底层结构

JDK 8 的 HashMap 使用 数组 + 链表或红黑树。数组中的每个位置称为桶；链表和红黑树用于组织同一个桶内的冲突节点。

  1. put 时对 key 的 hashCode 做扰动，计算桶下标。
  2. 桶为空直接放入节点；桶不为空则查找是否已有相同 key，存在则覆盖 value，不存在则新增到链表或树中。
  3. get 时先定位桶，再通过 hash 和 key 比较查找对应节点。
java
// JDK 8 的扰动与桶下标计算示意
int h = key == null ? 0 : key.hashCode();
int hash = h ^ (h >>> 16);
int index = (capacity - 1) & hash; // capacity 为 2 的幂

哈希冲突不要求完整 hash 相等

不同 hash 也可能映射到同一个桶。定位桶之后仍需比较 key，不能只比较 hash。HashMap 支持一个 null key 和多个 null value；key 判等使用引用相同或 equals 相等，正确实现的相等对象必须有相同 hashCode。

2.2 HashMap 在 JDK 7 和 JDK 8 中有什么区别？ ​

先明确：table 的每个位置是桶；多个 key 落入同一桶形成冲突；树化、退化只作用于单个桶，不是整个 Map 一起变成树。

比较项JDK 7JDK 8
数据结构数组 + 单向链表数组 + 单向链表或红黑树
普通链表插入头插法尾插法
扩容迁移头插迁移，会反转链表高低位拆分，保留各组相对顺序
无参构造的数组分配早期版本较早分配，部分后期更新版也是懒加载第一次 put 时初始化
并发安全不安全，扩容可能成环仍不安全，仍可能丢失更新等

树化与退化的条件 ​

  • 树化阈值：TREEIFY_THRESHOLD 为 8。但 JDK 8 普通 put 的循环计数方式意味着，通常是在已有 8 个节点的链表追加第 9 个节点时，才调用 treeifyBin。
  • 数组长度条件：table 长度至少为 64 才真正树化；长度小于 64 时优先扩容，用更多桶分散冲突。
  • 扩容拆分退化：树桶拆成高低位两组后，某一组节点数不超过 6，该组退回链表。删除树节点时的退化还涉及树的形态判断，不能把所有退化场景都说成严格按 6 判断。
  • 阈值缓冲：树化与拆分退化采用不同阈值，减少结构反复转换。

四个高频判断题

  1. 数组 16 个桶，某个桶追加后有 9 个节点 → 不树化，优先扩容。
  2. 数组 64 个桶，某个普通链表桶追加第 9 个节点 → 该桶尝试树化，其他桶不变。
  3. 数组 64 个桶，所有桶最多 5 个节点 → 保持链表结构。
  4. 数组 64 个桶，树桶扩容拆分后某一组只有 5 个节点 → 这一组退回链表。

容量与版本不要混淆

HashMap 的实际 table 容量是 2 的幂，不会出现“实际数组有 65 个桶”；构造时传入 65，通常会向上调整为 128。树化阈值常被简记为 8，但回答具体 put 触发时机时，要说明循环计数边界。

2.3 HashMap 的 put 方法的具体流程？ ​

put 实际调用 putVal，可拆成 定位桶位 → 冲突处理 → 收尾判断。

第一步：定位桶位 ​

table 未初始化或长度为 0 时调用 resize 初始化；然后按扰动后的 hash 和数组长度计算桶下标。

第二步：落桶，处理冲突 ​

  • 桶为空：直接新建 Node。
  • 桶已有节点：
    • 先检查桶首节点，hash 相等且 key 引用相同或 equals 相等，则命中已有 key。
    • 首节点是 TreeNode：执行红黑树查找、插入逻辑。
    • 普通链表：向后遍历，找到相同 key 则待覆盖；没找到则尾插新节点。达到树化计数条件后尝试 treeifyBin，数组长度不足 64 时改为扩容。

第三步：收尾 ​

  • 重复 key：返回旧 value；普通 put 覆盖 value，size 不变，不走新增后的扩容判断。
  • 新增 key：size 加 1，若 size > threshold 则 resize，通常容量翻倍。

2.4 讲一讲 HashMap 的扩容机制？ ​

resize 有两个作用：初始化 table，以及扩容并迁移已有数据。

  1. 触发时机：第一次 put；新增后 size 超过 threshold；树化时数组长度不足 64 也可能触发扩容。
  2. 扩容规则：通常容量翻倍。默认首次分配容量 16、负载因子 0.75、阈值 12；达到最大容量后不会继续翻倍，自定义负载因子会影响阈值。
  3. 迁移规则：单节点重新定位；树桶拆分；链表按 hash & oldCap 分成两组。
判断新桶下标含义
(hash & oldCap) == 0原下标留在低位组
(hash & oldCap) != 0原下标 + oldCap移到高位组

容量翻倍后，掩码只多出一位，因此不需要重新调用 key.hashCode。各组内部保持原有相对顺序；树桶拆分后节点数不超过 6 的组会退回链表。

          |
          +-- hash & 16 == 0 --> 新容量 32 的桶 3
          |
          +-- hash & 16 != 0 --> 新容量 32 的桶 19（3 + 16）

2.5 HashMap 在 JDK 7 下的多线程死循环问题？ ​

JDK 7 扩容迁移使用头插法，会反转链表。两个线程并发迁移时，可能交错读取、修改旧节点的 next 引用，最终形成环形链表；get 遍历该桶时无法结束，CPU 持续占用。

JDK 8 的迁移保留分组内的相对顺序，避免了经典的头插迁移成环问题。

解决经典成环问题，不代表线程安全

JDK 8 HashMap 仍可能发生数据覆盖、丢失更新和可见性问题。共享 Map 应使用合适的同步策略或 ConcurrentHashMap；复合业务操作应使用 compute、merge 等原子接口，或在同一把锁中完成。

三、Set 与集合体系篇 ​

3.1 HashSet 与 HashMap 的区别？ ​

  1. HashSet 实现 Set 接口，仅存储元素；HashMap 实现 Map 接口，存储 key-value。
  2. HashSet 底层用 HashMap 保存数据，元素作为 key，所有 value 使用同一个固定的 Object 占位对象。
  3. 不允许重复的判定沿用 HashMap 的 key 判等规则：引用相同，或 hash 相同且 equals 返回 true。
java
// HashSet 的实现片段
private transient HashMap<E, Object> map;
private static final Object PRESENT = new Object();

public boolean add(E e) {
    return map.put(e, PRESENT) == null;
}

放入集合后不要修改参与判等的字段

HashMap 的 key、HashSet 的元素若修改了参与 hashCode / equals 的字段，之后查找和删除可能定位到不同的桶，导致“明明存在却找不到”。自定义类应同时正确实现 equals 和 hashCode，优先使用不可变对象作为 key。

3.2 Hashtable 与 HashMap 的区别？ ​

nullkey 和 value 都不能为 null支持一个 null key 和多个 null value

实际类名是 Hashtable，不是 HashTable。新项目通常不建议使用它：并发 Map 优先考虑 ConcurrentHashMap，但后者也不允许 null key 和 null value。

线程安全范围仍需明确

Hashtable 的单次方法同步，不意味着多个方法组合的业务逻辑天然原子。选择容器时应先明确是单次访问、遍历，还是“判断后修改”等复合操作。
